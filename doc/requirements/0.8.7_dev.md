## 1. 设计哲学（用户拍板，全文档最高约束）

**对 AGENT 的使用方式与无多人版完全一致，一切只是多了适配多人的可选参数。**

- **不新增 MCP 工具、不新增 mp_* 能力**：`start_debug` 加 `players` 参数；
  `capture_game` / `lua.*` / `get_game_logs` / `run_scenario` 加 `player` 参数；
  `get_status` 返回里多一个 `clients` 数组。恒定 15 工具不变。
- **缺省语义统一**：`player` 缺省 = **多人局的 1 号玩家 / 单人局的唯一玩家**
  （确定性缺省，不是先到先得）。
- **单人局宽容**：单人调试中任何工具传了 `player` → 自动回退为单人行为 +
  响应附告知文案「当前为单人调试，player 参数已忽略；如需多人，请
  start_debug{players=N}」。
- **切换玩家窗口不是独立能力**：UI 操作走 lobby 总线 state 注入直达目标 VM，
  与编辑器 tab 焦点无关，无需切窗；只有截图依赖前台 tab——切焦/等帧/切回
  **内化在 capture_game 内部**，调用方无感。
- **玩家暂停/恢复是唯一的同族扩展**：`lua.set_pause{player, paused}` 加入
  lua.* 能力家族（非新 MCP 工具）——多人局测进场/断线/重连的刚需
  （官方 tab 暂停按钮同款语义：disconnect/reconnect_game_in_editor）。

## 3. 概念体系（全库全文档统一）

| 术语 | 定义 |
| --- | --- |
| **玩家号（player）** | 数编 player_setting 的玩家 key。**对外唯一多人参数名**，取值 1~4。游戏 VM 内可用 `base.local_player():get_slot_id()` 自证（实测 VM1→1/VM2→2） |
| **PIE 槽位（slot_id）** | 编辑器内嵌游戏实例的插件 UI 槽：单人 = `GamePlayInEditor`；多人 = `GamePlayInEditor<index>`（index = 拉起数组下标）。**内部实现细节，对外不暴露** |
| **归属映射表** | 桥 Lua 自持 `{ [player] = { slot_id, user_id, icon_color } }`，多人拉起时建立，新一局重建。player→slot_id 翻译全部经它 |
| **dbg 寻址** | bgd_dbg_cmd 载荷加 `target`（玩家号）；游戏侧非己丢弃；回执加 `from`（玩家号）+ `proto`（协议版本） |

**白话（为什么对外只有玩家号）**：用户心智是「玩家 1 / 玩家 2」（tab 标题、
调试信息面板、游戏内身份全是玩家号）；PIE index 只是拉起数组位置。两层翻译
内部完成，对外一个概念。多人参数名统一 `player`（不叫 client/slot）。

### 4.1 start_debug 多人扩展（答 v1#1~#8 / v2#1~2；用户场景 1）

MCP schema 增量（现有参数不动）：

```
start_debug {
  full?: boolean          -- 现状：强制全量（缺省 false = restart_last_debug 语义）
  players?: number | [ { player?: number, delay?: number } ]   -- 新增
  project_path?: string   -- 现状
}
```

- `players` 缺省 / =1 → **走现状单人路径，一字不动**。
- `players = N`（2≤N≤4）→ 多人路径：数编自动选人（下述），delay 全 0。
- `players = [...]` 数组 → 显式指定玩家与各自入场延迟（秒）；player 缺省按
  数组位置取自动选人结果的第 i 个；delay 缺省 0（官方默认，不预设递增——v1#5）。
- 多人路径的 `full` 语义对齐单人：`full=false` 且存在上次调试目录 →
  `use_last_debug_info`（last_debug_path 为 nil 时官方自动降级全量不报错——v1#2）。

**桥 handler `mp_start`（桥内部，非能力面）执行序**：

1. **互斥**（v1#7）：任一 `GamePlayInEditor*` 槽位在线 → 先发菜单「调试/停止」，
   等全部卸载；返回附 `stopped_previous=true`。
2. **缺省选人**：`obj_manager.get_entry_node_value(ENTRY_NODE_MAP_CONFIG, ...)`
   读三键（player_setting/opened_slots/user_ids），按 `pairs(player_setting)`
   序取 type='user' 且槽位 opened 的前 N 个——与官方 :1765 处理器同一遍历序
   （实测玩家1→uid100/玩家2→uid101），不发明新顺序。
3. **预校验**（v1#17，拒绝即报错，不触发官方静默降级）：
   地图已打开；地图类型非 lobby（`read_map_type` 是 menu_bar 局部函数不可达，
   补丁自持等价实现，开发时对照其源码逐行对齐）；每玩家 type='user'、槽位
   opened、user_ids 库存足够——失败返回精确原因 + 引导「去玩家设置面板启用
   槽位 X」（**本期不做 auto_open_slots**：写数编数据模型有脏标记副作用，
   test_res002 全开用不到——v1#3/v2#2）。
4. **字段补全**：Team = `player_setting[player][2]`（v2#3 拍板：test_res002
   多人逻辑自持，引擎侧无消费证据）；UserId = 官方分配规则；SlotID =
   `GamePlayInEditor<index>`；写 `menu_bar.debug_user_info[UserId] =
   { player, icon_color }`（缺失则 tab 标题退化、面板无玩家归属）。
5. **拉起**：`menu_bar.debug_save_as{ muti_debug_info=t, use_muti_debug=true,
   use_last_debug_info=... }`（纯 Lua 直调，已 spike 验证）。
6. **建立归属映射表** + 逐槽位轮询 `is_plugin_ui_loaded`（**必须 pcall**：
   未注册槽位抛错得 nil；true=在线/false=已卸载/nil=未注册），全部在线或
   超时 120s（对齐 start_debug），返回 `{ clients=[{player,slot_id,user_id,online}] }`。

### 4.2 dbg 寻址协议 v2（答 v1#12；dbg_bus 框架侧 + ui_loop 桥侧）

```
编辑器 → 游戏：{ id, cmd, args, target?, proto = 2 }
游戏 → 编辑器：{ id, ok, json, result, from?, proto? }
```

- **单人局不带 target**（player 参数无意义，协议字节级兼容现状，旧框架零感知）。
- **多人局恒带 target**（player 缺省=1，用户拍板确定性缺省）：
  - 游戏侧 dbg_bus：`target` 存在且 `get_slot_id() ~= target` → 直接丢弃；
    回执一律附 `from = get_slot_id()`、`proto = 2`；
  - 桥 ui_loop：配对待首个 `from == target` 的应答；**收到无 `from` 的应答 =
    对端旧框架** → 立即报错「游戏侧框架过旧：update-framework + build +
    restart_last_debug」，不等超时、不静默退化（v1#12）；
  - 超时 3s 兜底文案统一为「无响应（dbg_bus 未就绪？或目标玩家已暂停——
    可 lua.set_pause{player=N, paused=false} 恢复；或游戏侧框架需更新）」
    （暂停 VM 不应答，实测；与 §4.5 同一文案模板）。
- **capture_game 与 get_game_logs 的 player 维度不经过 dbg 总线**（编辑器侧
  机制），旧框架多人局照样可用——只有 lua.* 定向依赖框架版本（§8 矩阵）。

### 4.3 get_status 扩展与门禁修复（答 v1#9）

- `get_status` 增量返回 `clients` 数组（既有字段不动）：
  `{ player, slot_id, user_id, online, paused }`——数据源 = 归属映射表 +
  同步槽位枚举，**不做广播收集**（同步接口不阻塞等异步；VM 活性由定向命令
  顺带确认）；`paused` 为桥自持标注（漂移风险见 §4.5）。
- `debugging` 判定改「`GamePlayInEditor` 或任一 `GamePlayInEditor1..4` 在线」；
  ui_loop `is_debugging()` 门禁同改——修复纯多人局 lua.* 全灭（实测缺口）。

### 4.4 lua.* 全命令 player 参数（用户场景 3）

- ui_loop passthrough 加 `player` → 经归属映射表译 target 进 bgd_dbg_cmd；
  游戏侧 dbg_commands 零改动（过滤在 dbg_bus 总线层）。
- 缺省 = 多人局 1 号玩家 / 单人局唯一玩家（不带 target）。
- 单人局带 player → 自动回退单人行为 + 响应附告知文案（§1 哲学）。
- 多人局带不存在的 player → 报错「玩家 N 不在线（当前在线：1,2，
  get_status 可查）」。

### 4.5 玩家暂停/恢复（lua.set_pause；用户补充：进场/离场/重连测试刚需）

- 能力条目 `lua.set_pause { player, paused: boolean }`（write；lua.* 家族同族
  新增一条，非新工具）。桥 handler `mp_pause`（mp_debug.lua）：
  `paused=true` → `sceneMgr:disconnect_game_in_editor(slot_id)`；
  `paused=false` → `sceneMgr:reconnect_game_in_editor(slot_id)`——
  官方 tab 暂停按钮同款调用（menu_bar.lua:656-664）。
- 语义 = **断线/重连模拟**：disconnect 后该客户端 VM 停止 tick（dbg 命令不应答、
  日志无新行、画面定格最后一帧）；host 局不销毁（只有最后一个客户端**关闭 tab**
  才毁局，暂停不算）；reconnect 后客户端重新连入——正是进场/离场/重连测试场景。
- 缺省语义同哲学（多人局缺省 player=1）；单人局槽位**官方就没有暂停按钮**
  （menu_bar.lua:700-715 单人槽位只注册关闭/切换）——单人局调 set_pause
  报错「单人调试槽位无暂停能力」。
- **暂停态标注**：归属映射表自持 `paused` 标志并随 get_status.clients 返回。
  已知漂移风险：用户手动点 tab 暂停按钮不经过桥，自持状态会失真——
  官方无暂停态查询接口（§7 spike 评估项）；漂移只影响标注不影响功能，
  lua.* 超时报错文案统一为「无响应（dbg_bus 未就绪？或目标玩家已暂停——
  可 lua.set_pause{player=N, paused=false} 恢复；或游戏侧框架需更新）」。
- **完整离场（关 tab）不进本期**：已实测定案不可行——hide 后 C++ 侧槽位会话
  即销毁，再 show_game_in_editor 会挤掉在局玩家并只重建单客户端会话
  （两轮实验一致，研究文档 §4.1）。断线/重连测试用暂停/恢复覆盖。

### 4.6 capture_game player 参数（用户场景 2；答 v1#11/#13）

- 视口枚举正则改 `^ui%-%d+%-GamePlayInEditor(%d*)$`（main.lua
  get_game_view_rect）：无后缀 = 单人局；`%d*` = PIE index → 归属映射表反查
  玩家号。get_game_view_rect 保持纯读（read 级无副作用）。
- 桥 handler `mp_switch`（桥内部 write，非能力面）：`_G.ui.switch_page(slot_id)`
  + `sceneMgr:set_game_ui_focus(slot_id)`，返回 `{ rect, previous }`；
  不加 reconnect（v1#10：官方切 tab 不自动 reconnect，不预设）。
- **capture.rs 执行序**（player 给定或多人局缺省=1 时）：
  ① `mp_switch{player}`（切焦，拿回 previous）→ ② `get_game_view_rect{player}`
  （纯读）→ ③ exe sleep `wait_ms`（等帧，**缺省 200ms**——实测切焦后 45ms
  即合成完成，研究文档 §4.2；200ms 含充足余量）→
  ④ WGC 截编辑器主窗口 + rect 裁剪（现有链路不动）→ ⑤ 切回 previous
  （`restore` 参数缺省 **true**——截图不打扰用户当前焦点；连续批量截时可
  显式 restore=false 省去反复切换）。
- 暂停玩家截图 = 定格最后一帧画面（disconnect 后 VM 停 tick，实测语义），
  响应附 hint「该玩家已暂停」。
- 单人局带 player → 回退 + 告知文案（§1）；多人局画面歧义不存在
  （缺省=1 号玩家），**不产生新报错**。
- **q+player 组合**：find_ui 先定向拿游戏逻辑 rect → 该玩家的 `lua.game_info`
  逻辑分辨率换算 → crop 夹到该视口。q 不带 player 且多人局 → 按 1 号玩家
  处理 + 响应附 hint「多人局未指定 player，已按玩家 1 截取」。

### 4.6 get_game_logs player 参数（用户拍板：旧逻辑全保留 + tee 数据源）

- **文件型管线一字不动**（多天重复收纳/match 正则/errors 上浮/同条 ×N）。
- `player` 给定 → 在线走 tee 通道（桥 mp_debug.lua 常驻监听
  `EVENT.add_info_list` 的 `debug_client_info` 投递，面板已把 userID 映射成
  玩家号；**回调签名 `function(self, module, data)`、必须返回 nil**——三坑见
  研究文档 §6），tee 进每玩家环形缓冲（1000 条/人，新一局拉起时清空，
  另支持 `clear=true` 手动清空）。
- tee 行 `{ player, type, message, frame }` 回传 exe 后，**复用 logs.rs 现有
  match/errors/同条收纳处理**——分玩家日志与文件日志的过滤体验一致。
- `player` 给定但编辑器离线 → 报错「分玩家日志需编辑器在线（tee 通道）；
  文件日志请省略 player」。
- 边界（文档化）：tee 只含面板管线放行的日志（无 file_location 的部分 C++
  日志不在内）；tee 无历史（注册时点起）；服务端日志仍走文件型；
  单人局日志 player=nil 归「未标记」，player=1 查询命中未标记行。

### 4.8 run_scenario 适配

- 步骤级 `player` 字段透传到 invoke（lua.*）/capture/capture_ui/logs/
  wait_for/assert_text 各 op；场景级 `default_player`（可选）作为步骤缺省。
- 跨玩家交替操作压测进验收（v1#15：20 步交替跑绿，逼出切焦/坐标耦合问题）。

## 6. 实现纪律（改动红线，全部有前科/实证依据）

1. **无图不碰 DI**：mp_debug.lua 一切 menu_bar/obj_manager 获取推迟到
   load_map_done 后（前科 test/requirements/debug-muti-debug-crash.md）。
2. **不 require 'ui.menu_bar' 于模块加载期**（顶层副作用打乱官方初始化）；
   用时 `package.loaded['@xdeditor/ui/menu_bar']`，未加载 = 明确报错。
3. **枚举槽位必须 pcall**（is_plugin_ui_loaded 对未注册槽位抛错）。
4. **tee 回调返回 nil + 首参 self**（研究文档 §6 踩坑①②）。
5. **单人局协议字节级不变**；多人局定向遇旧框架必须响亮报错引导升级，
   禁止静默退化（v1#12）。
6. 补丁文件拆分：新功能集中 `patches/xdeditor/bgd_mcp_bridge/mp_debug.lua`，
   main.lua 只加 setup 挂载一行（单文件 500 行纪律）。
7. 游戏侧改动最小化：只动 dbg_bus.lua；dbg_commands.lua 不改。
8. 缺省语义全库统一：player 缺省 = 多人 1 号 / 单人唯一；单人局带 player
   = 回退 + 告知（文案 §1 统一模板）。

## 7. spike 结论（2026-09-02 全部实测回填，证据见研究文档 §4.1/§4.2）

| 问题 | 结论 |
| --- | --- |
| 切焦后等帧下界 | **45ms 即合成完成**（像素采样实测）；wait_ms 缺省定 **200ms**（余量充足） |
| Delay=0 同帧拉起稳定性 | 2 人局累计 3 次成功（2026-09-01×1 + 09-02×2）；4 人局在验收总表复跑 |
| 暂停态检测可行性 | **无官方查询接口**（sceneMgr 方法清单实证）；定案 = 桥自持 paused 标注 + 文档化手动按钮漂移 |
| 离场后局内重进 | **实测不可行**（挤掉在局玩家重建单客户端会话）；非目标条款落地 |

### 9.1 MCP 会话全流程（2 人局）

```
# 1. 拉起 2 人局（等价于原来 start_debug 的日常用法，只多一个 players）

#    玩家 2 打开背包（带 player）
invoke_capability { id="lua.tap", args={ q="背包", player=2 } }

# 4. 分别截图（内部自动切焦/等帧/切回，调用方无感）

capture_game { player=2, q="背包", max_width=640 }  → 玩家 2 背包局部

→ 玩家 2 的背包相关行（同条收纳 ×N / errors 上浮照常生效）

# 6. 断线/重连测试：暂停玩家 2 → 定向命令超时带恢复引导 → 恢复
invoke_capability { id="lua.set_pause", args={ player=2, paused=true } }
invoke_capability { id="lua.eval", args={ code="return 1", player=2 } }
→ 超时报错「……或目标玩家已暂停——可 lua.set_pause{player=2, paused=false} 恢复……」
invoke_capability { id="lua.set_pause", args={ player=2, paused=false } }
→ 玩家 2 客户端重新连入（get_status.clients[2].paused=false）

# 7. 停止（现状不变，多人局全槽位卸载已实测）
stop_debug {}
```
