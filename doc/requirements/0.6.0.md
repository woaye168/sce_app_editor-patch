# 0.6.0 版本计划：宿主生命周期联动 + 运行时常量通知 + bgd_sce_appsdk 架构升级

> 状态：待评审（确认后开发）
> 范围：bgd_sce_tools / sce_app_editor-patch / sce_app_visual-injector / bgd_sce_plugins（→ bgd_sce_appsdk）

## 需求与评估

### R1：宿主关闭时联动关闭其静默自启的应用

- **问题**：静默自启的应用在 bgd_sce_tools 关闭后继续运行，生命周期不受控。
- **评估**：合理且必要。自启应用是宿主管辖的子进程，应跟随宿主生命周期。
- **方案**：宿主退出时（Tauri 关闭事件）对所有运行中的已安装应用广播 `--quit`（应用已有的优雅退出信号），短等待后兜底 taskkill。范围 = 全部已安装且正在运行的应用（不限于本次自启拉起的——用户手动打开的也属于宿主管辖会话）。

### R2：宿主切换项目时，注入的项目路径实时更新

- **问题**：宿主「项目」页切换项目后，编辑器补丁已注入的 `_project_root.lua` 不更新（应用仅在自己 refresh 时同步；静默驻留时无感知）。
- **评估**：合理。应用侧已有自同步逻辑，缺的是宿主→应用的实时通知通道。
- **方案**：见 R3 的通知机制（同一通道承载项目切换）。

### R3：运行时共享常量文件 + 宿主→应用通知机制

- **问题**：
  1. `_project_root.lua` 注入在 unwatch 模块目录内，但「当前项目路径」是所有模块都可能用的共享常量，位置不合理；
  2. 未来还会注入其他公共常量，文件名不应绑定单一键值；
  3. 需要宿主→应用的解耦通知（切项目等时刻触发常量更新）。
- **评估**：方向正确。**不推荐持久 IPC 观察者模式**（连接管理/断线重连/进程发现都是负担）。采用 **CLI 通知约定**：宿主在事件时刻调用应用的 notify 子命令，应用自行决定常量写哪、如何刷新——宿主零知识、应用自治，职责清晰、天然解耦。
- **方案**：
  1. **共享常量文件**：`<库require根>/sce_app_editor-patch/bgd_runtime.lua`（补丁框架根目录，所有模块可 require），内容为 `return { project_path = "..." }` 表结构（未来加键不改结构）。
  2. **通知约定（appsdk 级协议）**：宿主调 `<app_exe> notify <key>=<value> [...]`。editor-patch 的 notify 实现：原子重写 bgd_runtime.lua + 若 GUI 实例在运行则发信号让其刷新（复用单实例事件通道）。unwatch 等模块改为读 bgd_runtime.lua。
  3. **宿主侧**：切换项目（select_project）时，对每个静默自启中的应用执行 notify（异步、失败静默不阻塞）。
- **迁移兼容**：旧的 `unwatch/_project_root.lua` 由新逻辑直接覆盖替换（工具未对外发布，不做兼容）。

### R4：bgd_sce_plugins → bgd_sce_appsdk 架构升级

- **问题**：bgd_sce_plugins 目前只有 registry.json 一个用途；而 sce_app_* 各应用重复实现了同一套基建（单实例/--background/--quit/CLI 分发/.bgd 日志/--project-path 参数/升级协议/通用 egui 界面骨架），重复必然漂移（0.5.10/0.5.11 的修复已证明）。
- **评估**：有必要且时机合适。registry 留在同仓库合理（分发元数据与 SDK 同源同版本）。通用界面骨架（项目栏/设置页/关于页等，见本轮截图）也可作为 SDK 的 UI 组件提供。
- **方案**：
  1. 仓库改名 `bgd_sce_plugins` → **`bgd_sce_appsdk`**（GitHub rename 保留重定向与 PAT 授权）。
  2. 仓库双职责：`registry.json`（分发清单）+ **Rust crate `bgd_appsdk`**（lib 目标），首批沉淀：
     - 单实例 + 唤起/退出事件通道 + 看守线程（Win32 驱动，0.5.10/0.5.11 定稿的实现）；
     - CLI 骨架（--project-path/--background/--quit/notify 参数解析与分发）；
     - .bgd 日志（按日期分文件）、应用配置持久化（最近项目等）；
     - 通用 egui 组件（项目选择栏/设置页/关于页骨架）。
  3. 迁移顺序：先 editor-patch（基建最全，抽完即 SDK 定型），再 visual-injector。

### R5：registry 极简化为「名称 + 下载位置」，元数据归各应用自治

- **问题**：当前 registry.json 每个条目含 version/tag/description/author/asset_name——**每次发版都要同步改 registry**（机械、易漏、本质上重复了应用自身的信息）。
- **评估**：非常好的收敛。registry 只承担「有哪些应用、去哪下载」（稳定不变），易变的版本/描述/作者等全部从应用各自的约定文件读取——registry 一次写入永不改动，发版不再需要碰它。
- **方案**：
  1. **registry.json 只保留**：`[{ "id", "name", "repo" }]`（repo 即下载位置来源；私有仓库经 API 取 `releases/latest` 定位 asset）。
  2. **应用侧约定文件 `<repo>/app.json`（仓库根，纯静态元数据，不含版本）**：`{ "id", "name", "description", "author", "asset_name" }`。
  3. **CI 发版时合成发布元数据 asset `app-release.json`**：= app.json 静态内容 + `version`（tag）+ `release_notes`（版本说明，CI 按 git log 区间生成，与 GitHub Release notes 同源）。随 exe 一起作为 release asset 上传——版本号是 CI 流程产物，仓库文件永不改版本。
  4. asset 文件名各应用恒定（如 `sce_app_editor-patch.exe`），配合 `releases/latest` API 始终指向最新版——不需要在文件名里带版本号，也不需要每次发版改任何清单。
  5. **宿主读取链**：registry（raw）→ `repos/<repo>/releases/latest` → 读 `app-release.json` asset（版本/描述/作者/版本说明/asset 名）→ 下载 exe asset（均走 net.rs 认证客户端）。
  6. **应用市场「升级」按钮展示版本说明**：升级确认/执行时展示 app-release.json 的 release_notes（当前版 → 新版本 + 变更说明），填补目前升级无任何说明的空白。

## 里程碑与版本计划

| 阶段 | 内容 | 仓库：版本 |
| --- | --- | --- |
| A1 | R1 宿主退出联动关闭应用；R3 宿主 notify 广播 | bgd_sce_tools **0.6.10** |
| A2 | R2+R3 bgd_runtime.lua 共享常量 + notify 子命令 + unwatch 迁移 | sce_app_editor-patch **0.5.12** |
| B1 | SDK 抽取（bgd_appsdk crate）+ 仓库改名 + R5 registry 极简化 + 各应用 app.json 约定文件 + editor-patch 迁移 | bgd_sce_appsdk（新）、sce_app_editor-patch **0.6.0** |
| B2 | visual-injector 迁移 SDK | sce_app_visual-injector **0.5.0** |
| B3 | 宿主 registry URL/读取链（app.json 约定 + releases/latest）/文档同步改名 | bgd_sce_tools **0.7.0** |

版本规则（按要求）：改名落地时，所有相关项目**中间版本号 +1、尾版本号清 0**（0.5.x→0.6.0、0.6.x→0.7.0、0.4.x→0.5.0）。

## 改名影响清单（B 阶段逐项执行）

- bgd_sce_tools：`DEFAULT_REGISTRY_URL`（raw URL 中的仓库名）、AGENTS/README 引用。
- sce_app_editor-patch / visual-injector：AGENTS.md 中 registry 仓库链接、发布说明。
- registry.json 内各条目 `repo` 字段指向不变（仍指各应用自身仓库）。
- GitHub PAT（fine-grained）：改名后授权自动跟随，但需验证。
- 本地工作副本：git remote set-url 更新（三处本地目录）。

## 验收标准

1. 关闭 bgd_sce_tools 后，其静默自启的应用进程全部退出。
2. 宿主切换项目后 5s 内，`<库require根>/sce_app_editor-patch/bgd_runtime.lua` 的 project_path 更新为新路径（无需重启编辑器补丁应用）。
3. editor-patch 的 unwatch 等模块从新共享常量文件读取项目路径（运行时不报错）。
4. B 阶段后：editor-patch/visual-injector 构建只依赖 bgd_appsdk 提供上述基建，无重复实现；registry 正常工作；改名后应用市场/自我更新链路不受影响。
5. R5：任意应用发新版后，**不改 registry.json**，应用市场即可显示新版本与描述（来自 CI 合成的 app-release.json asset），「升级」时展示版本说明，下载到新 asset。
