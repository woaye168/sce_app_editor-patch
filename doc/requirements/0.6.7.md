# 0.6.7 需求与方案：appsdk 发布 crates.io + CLI 脚手架 + 应用页现代化加载 + 窗口居中

> 状态：开发中（R1 待 crates.io token 配置后收尾）

## R1：bgd_appsdk 发布 crates.io，应用侧改版本号依赖

- **方案**：appsdk CI（tag 触发）执行 `cargo publish`（token 走 secret `CARGO_REGISTRY_TOKEN`）；两应用 `bgd_appsdk = "0.1"`（crates.io 版本号依赖，自动取兼容最新）。注意：crates.io 为公开注册表，包发布后源码公开可查。
- **前置**：用户配置 crates.io token 到 secret（已给出步骤）。

## R2：appsdk CLI 脚手架（快速创建 sce_app_* 标准应用）

- **方案**：appsdk 增加 `[[bin]] bgd_appsdk`（cargo publish 随包发布的工具二进制，安装方式 `cargo install bgd_appsdk`）。子命令 `bgd_appsdk new <app-id> --name <中文名>`：生成标准应用骨架（Cargo.toml（git/版本依赖 appsdk + eframe/clap 等）/src/main.rs（AppShell + 单实例 + --background/--quit/notify 全接入的最小可运行示例）/app.json/release.yml/AGENTS.md）。

## R3：应用页「假死感」现代化消除

- **根因**：Tauri 命令是**同步阻塞**执行的 Rust 函数（reqwest blocking 在命令线程里跑），前端 invoke 并发发起的多个请求在后端串行排队，且与 UI 消息循环争用——表现为窗口拖不动、菜单切不走（数秒）。
- **方案（现代方案）**：后端命令改 **async（tauri async command + reqwest 异步 client）**——网络等待期间让出线程，UI 全程可交互。具体：
  1. 引入 `tauri = { features = ["async"] }` 所需的 tokio（仅必要的 rt feature）；
  2. net.rs 增加 `async_http_client`（reqwest async）；
  3. 应用市场相关命令（fetch_app_registry / enrich_app / install_app / 及 fetch_release_meta/download_asset 链路）改 async fn，invoke 即真正异步并发；
  4. 前端保持逐应用并发调用（已有骨架 + 逐条回填）。

## R4：应用窗口屏幕正中显示

- **问题**：打开的应用窗口出现在屏幕中心偏左上约半个身位（egui 默认定位行为）。
- **方案**：SDK `ui::AppShell::run` 在 ViewportBuilder 增加 `with_position()`，按当前显示器尺寸与窗口尺寸计算居中坐标（`monitor_size` 不可得时用固定初始位置 + `with_center` 不可用（egui 0.29 无 API）→ 用 `ViewportCommand::CenterOnScreen` 在首帧发送，或以 with_position 估算主屏中心）。取实测可靠的一种。

## 验收

1. 两应用 `cargo update -p bgd_appsdk` 拉到 crates.io 版本；CI 出包正常。
2. `bgd_appsdk new demo-app --name 示例` 生成的项目可直接 cargo run 起壳。
3. 应用页加载期间窗口可自由拖动、菜单可自由切换。
4. 打开的应用窗口出现在屏幕正中央。
