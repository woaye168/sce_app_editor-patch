# 0.5.6 需求与方案：MCP 日志工具优化 + 静默自启完善 + 易用性细节

> 状态：已实现（R1–R6 完成，测试报告见 test/0.5.6/）
> 承接：0.5.5（MCP 应用自持 + 真后台截图 + 应用自启动初版）
> 说明：本轮为 0.5.5 交付后的细节问题修正，共 6 个需求（R1–R6）。

## R1：日志工具 get_logs → get_game_logs 重命名与全面优化

### 问题

1. 工具名 `get_logs` 语义模糊，AGENT 搜索「获取游戏日志」等自然语言不易命中。
2. `project_path` 参数意义不大（应用已能自动解析项目）。
3. 返回值各日志项没有说明，AGENT 不理解每个 key 是什么日志。
4. 日志源覆盖不全：缺编辑器自身日志（`lua-editor-*.log`）；现有 key 命名（client/server_core/server_lua）语义不清。
5. source 参数取值与返回 key 不对应，且缺少按类聚合与「游戏日志」这个最常用的默认集合。

### 方案

**1. 工具重命名**：`get_logs` → `get_game_logs`。description 重写为覆盖高频检索词的文案：
「获取游戏日志/编辑器日志/MCP桥日志的最新文件信息（路径/大小/创建/修改/行数）。tail_lines=0（默认）只返回文件信息不返回内容；tail_lines>0 时额外返回末尾内容。离线可用（不要求编辑器在线）。」

**2. 参数收敛为两个**：
- `source`（见下）
- `tail_lines`（默认 0）

`project_path` 参数**移除**；项目解析链：应用最近项目（GUI 选过即记住）→ 在线编辑器当前地图（get_status.map_path）→ 都不可用时明确报错「请先在『编辑器补丁』应用中选择过项目」。

**3. 日志源清单（6 个具体 key）**：

| key | 文件 | 说明（返回值的 desc 字段） |
| --- | --- | --- |
| `bridge_audit` | `<运行根>/logs/bgd_csharp/audit-*.log` | MCP桥审计日志（编辑器补丁 bgd_mcp_bridge 的 write/danger 能力调用审计） |
| `bridge_main` | `<运行根>/logs/bgd_csharp/bgd_csharp-*.log` | MCP桥入口日志（编辑器补丁 bgd_mcp_bridge 服务启动/请求处理日志） |
| `xdeditor_client` | `<运行根>/logs/lua/lua-editor-*.log` | 编辑器日志（星火编辑器操作动作及运行日志） |
| `game_client` | `<运行根>/logs/lua/lua-game-*.log` | 游戏客户端日志（调试游戏后产生） |
| `service_core` | `<运行根>/logs/server/core-game-server-*.log` | 服务器底层日志（游戏服务端底层框架日志） |
| `game_server` | `<运行根>/logs/server/lua-game-server-*.log` | 游戏服务端日志（游戏服务端自身代码日志） |

**4. source 取值（动态聚合，非硬编码）**：
- 具体 key：上表 6 个（`bridge_audit` / `bridge_main` / `xdeditor_client` / `game_client` / `service_core` / `game_server`）
- **聚合值 = 动态前缀匹配**：source 不是具体 key 时，按「key 前缀 + `_`」动态匹配所有日志项（如 `bridge` 命中全部 `bridge_*`）。**不写死聚合清单**——未来新增任何 `xxx_yyy` 形式的日志源，`xxx` 自动成为可用聚合值，零改动扩展
- `all` → 全部日志项
- **缺省/空值 = `game`**（即动态命中 `game_client` + `game_server`，最高频场景）
- 未匹配到任何日志项的 source 值：明确报错并列出当前可用 key

**5. 返回值结构**：每项增加 `desc` 字段（上表说明文案），便于 AGENT 直接理解；`logs_root` 保留。示例：

```json
{
  "logs": {
    "game_client": {
      "desc": "游戏客户端日志（调试游戏后产生）",
      "path": "D:/sce_online/logs/lua/lua-game-2026-08-19 08_45_32_932.log",
      "size": 13020, "lines": 108,
      "created": "2026-08-19 08:45:32", "modified": "2026-08-19 08:47:13"
    }
  },
  "logs_root": "D:/sce_online/logs"
}
```

**6. CLI 同步**：`sce_app_editor-patch logs [source] [行数]` 的 source 取值与返回值结构与 MCP 完全一致（同一实现）。

## R2：输出路径斜杠统一为 `/`

- **问题**：MCP/CLI 返回值中的路径混用 `/` 与 `\`（如 `D:/sce_online\logs\bgd_csharp\...`）。
- **方案**：所有对外输出（MCP 工具返回值、CLI 打印的 JSON）中的路径统一规整为正斜杠；举一反三排查：`get_game_logs`、`capture_game`（path）、`editor_start` 等返回值，及 core/bridge_client.rs、core/capture.rs、core/editor.rs、cli.rs、mcp.rs 中所有 `display().to_string()` 出口（统一经一个 `to_slash()` 辅助函数）。

## R3：「随主程序启动」更名「静默自启」并修复黑终端与重开问题

- **更名**：UI 文案与设置文档统一为「静默自启」（设置键 `auto_start_apps` 不变）。
- **修复黑终端**：自启动拉起与进程探测（is_app_running 的 PowerShell 调用）等所有子进程创建一律加 `CREATE_NO_WINDOW`，不再闪现黑色控制台窗口。
- **修复「关闭之后就打不开了」**：定位并修复（初步怀疑：进程探测误判——如匹配到残留的同名进程/探测调用本身异常导致守卫始终认为在运行）。验收：关闭自启应用后，点「打开」能正常再次启动。
- **保持逐应用配置**：静默自启是应用级勾选项，不是所有应用默认行为。

## R4：宿主（bgd_sce_tools）启动速度优化

- **问题**：当前启动明显变慢——自启动流程中对每个配置应用都做一次 PowerShell `Get-CimInstance` 全量进程查询（每次 ~1-2s），且串行阻塞 GUI 启动。
- **方案**：
  1. **异步拉起（核心）**：静默自启流程整体放后台线程异步执行，宿主 GUI 首屏显示完全不等它——自启应用陆续在后台起来即可；
  2. **一次查询，内存复用**：后台线程内只调一次进程列表，所有自启应用的「是否在运行」判断在内存中匹配（消除每个应用一次 PowerShell 查询的串行开销）。

## R5：编辑器补丁应用默认静默自启 + 单开唤起

- **默认开启**：「编辑器补丁」应用安装后默认勾选静默自启（宿主侧对该应用 id 首次写入 `auto_start_apps` 默认值；用户手动取消后不再重置）。
- **静默运行形态**：应用支持 `--background` 参数启动——不显示主窗口，驻留后台（为 MCP/CLI 链路提供最近项目等状态；窗口需要时再唤出）。
- **单开唤起**：应用自身做单实例（命名互斥体）：
  - 宿主「打开」（或用户再次双击 exe）且实例已在运行时，**不新建进程**，而是向已运行实例发「显示窗口」信号（命名事件 + 运行实例轮询检测），把窗口唤到前台；
  - 未运行则正常启动（按是否带 `--background` 决定显隐）。

## R6：内核界面「复制 MCP 配置」按钮

- **位置**：sce_app_editor-patch「内核」标签页。
- **行为**：点击按钮把以下 JSON 复制到剪贴板，`<安装目录>` 替换为真实宿主安装目录（由应用 exe 自身路径上溯两级推导：`apps/editor-patch/sce_app_editor-patch.exe` → 宿主根）：

```json
{ "mcpServers": { "bgd-sce": { "command": "<安装目录>/apps/editor-patch/sce_app_editor-patch.exe", "args": ["mcp"] } } }
```

- 按钮旁给一句说明文案（AI 客户端 MCP 配置入口；粘贴到客户端 MCP 设置即可）。

## 验收标准

1. MCP 客户端用自然语言「获取游戏日志」能命中并正确调用 `get_game_logs`；默认调用返回 game_client + game_server 两项（含 desc）。
2. 输出 JSON 中所有路径只含 `/`。
3. 宿主启动无黑终端闪现、启动时间恢复到加自启动机制之前的水平；关闭自启应用后可再次打开。
4. 编辑器补丁应用默认静默自启；重复「打开」只唤起窗口，系统内始终只有一个应用进程。
5. 内核页点「复制 MCP 配置」后剪贴板内容可直接粘贴到 MCP 客户端使用（路径真实有效）。
