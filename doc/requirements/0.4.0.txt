sce_app_editor-patch 0.4.0 —— C# 扩展模块注入 + 编辑器内 HTTP 服务（外部 AI 控制调试的地基与首版）

目标：让星火编辑器进程内能加载并运行**我们自己编写的 C# DLL（bgd_mcp_bridge.dll）**，并在其上一次性交付完整底层能力：HTTP JSON-RPC 服务 + MCP（Streamable HTTP）+ 调试/文件等全命令控制 + 隐藏窗口 + 弹窗抑制 + 原生事件推送。
范围说明：本版一次性把底层做完（用户明确要求 2026-08-16）；仅 stdio-only 客户端 shim、更多业务方法/事件按需扩充留后续。

**当前状态：冒烟测试已通过（2026-08-16）**——编辑器内成功弹出测试 WinUI 窗口，探针日志确认我们的 C# 代码在编辑器进程内执行（pid 实证）。
研究细节已全部沉淀：doc/research/csharp-module-injection.md（C# 注入）、doc/research/editor-debug-control.md（调试启停机制与方案对比）。

〇、硬性约定（本版本新增，优先级最高）

1. **命名**：dll 文件名与程序集名 = `bgd_mcp_bridge`（bgd_mcp_bridge.dll）；补丁模块 id 同名（patches/xdeditor/bgd_mcp_bridge/main.lua）。冒烟期的 BgdBridge / bgd_bridge_test 命名全部废弃。
2. **部署时机**：dll **在勾选（启用）补丁模块时才部署**进引擎版本目录（version-<api>/），同时注入 sce.deps.json 条目；取消勾选时移除 dll 并摘除 deps.json 条目。内核「应用补丁」不负责 dll 部署。deps.json 的备份（sce.deps.json_bak）在首次注入时建立，还原补丁时整体恢复。
3. **禁止硬编码路径**：
   - 编辑器根按 0.1.0 定位链获取（项目 project/map_settings.json → api_version；项目 script/tsconfig.json → typeRoots → 提取编辑器根；api_pak_version.json → 包版本）。
   - 引擎运行根（D:/sce_online 一级）由编辑器根推导（编辑器根的父目录的父目录，如 D:/sce_online/Update/editor-pd.spark.xd.com → D:/sce_online），version-<api_version> 目录即其下。locate.rs 需新增此推导并缓存。
   - C# 侧日志目录 = <引擎运行根>/logs/bgd_csharp/，按日期+小时滚动（bgd_csharp-YYYY-MM-DD-HH.log）。C# 侧不得写死该路径——由进程主模块路径（Process.MainModule）在运行时推导运行根。
4. **路径风格统一**：所有仓库（本仓库 + bgd_sce_framework + bgd_sce_plugins + sce_app_visual-injector）源码/文档中的路径一律使用正斜杠形式（C:/xxx/xxx），禁止 \ 与 / 混用。Rust/Lua/C#/TS 拼接路径统一用正斜杠（Windows API 与引擎均兼容）。
5. **最终目标**：推送 GitHub 私有仓库，打 tag 触发 CICD 自动构建发布。CI 需新增 .NET SDK 步骤编译 csharp/bgd_mcp_bridge，产出的 dll 由 Rust 编译期嵌入 exe（include_bytes!）随单一 sce_app_editor-patch.exe 分发（asset_name 不变）。

一、研究成果（已实测验证，详见 doc/research/csharp-module-injection.md）

【1】运行环境
- 编辑器运行目录下按 api 版本分目录存放引擎：version-13（api 13）等。
- version-13 内嵌完整 CoreCLR（net9.0 自包含 .NET 9.0.13）：coreclr/hostfxr/hostpolicy + sce.runtimeconfig.json。
- 托管程序集：sce.dll（主编排）、scemodule.dll（官方模块集）、scecustomcontrol.dll 等；宿主 WinUI 3.1.6（≈ WASDK 1.6.250205002）。
- 运行时自带 system.net.httplistener.dll / system.net.sockets.dll —— C# 侧开 HTTP 服务的条件天然具备。

【2】官方模块机制（Lua → C#）
- SCE.Common.create_csharp_module('Name') → sceengine.dll → 托管事件 Event.CreateModule → sce.dll App.cs:181-213 按名字硬编码 switch 分派，**未知名字返回 null，不可扩展**。
- 模块类约定：public sealed class Xxx : WindowSCE, IServiceModule（WinUI 3 窗口 + DI 注册）。

【3】关键注入点（已实测打通）
- sce.dll App.cs:214-217 订阅 Event.ActivateWindow，处理是**泛型反射**：
  `((Window)Activator.CreateInstance(Type.GetType(eventData.GetValue("ModuleType").GetString())))?.Activate();`
- Lua 侧 API（menu_bar.lua:2879 注释残留实证）：`SCE.Common.csharp_activate_window('命名空间.类名, 程序集名')`
- 实测：必须传程序集限定名；入口类继承 Window + 无参 ctor 即可被创建并 Activate()。

【4】程序集解析（已实测打通）
- dll 复制进 version-<api>/，sce.deps.json 追加：
  - targets[".NETCoreApp,Version=v9.0/win-x64"]["bgd_mcp_bridge/1.0.0"] = { runtime: { "bgd_mcp_bridge.dll": { assemblyVersion, fileVersion } } }（条目都在 win-x64 子组，顶层 v9.0 组为空）
  - libraries["bgd_mcp_bridge/1.0.0"] = { type: "project", serviceable: false, sha512: "" }
- 无需声明 dependencies（引用的 Microsoft.WinUI / WinRT.Runtime / Microsoft.Windows.SDK.NET 已在宿主依赖图中）。

【5】C# 侧编译方式（实测修正，重要）
- **不要用 WASDK NuGet 包**：Microsoft.WindowsAppSDK 1.6 的 MrtCore.PriGen 在 dotnet SDK 10 上缺 ExpandPriContent 任务，构建失败。
- 实测可行：**直接 Reference 宿主 version-13 自带投影程序集**（microsoft.winui.dll / winrt.runtime.dll / microsoft.windows.sdk.net.dll），TFM=net9.0-windows10.0.19041.0，零 NuGet 依赖，版本与宿主严格一致。

【6】Lua 侧调用要点（实测踩坑）
- **SCE 不是全局**：补丁模块必须 `local SCE = ImportSCEContext()`。
- **base.timer 签名是 (timeout, count, on_timer)**；单次延迟用 **base.wait(timeout, fn)**。
- **时序**：补丁入口执行时托管侧事件订阅未必就绪——base.wait(5000) 延迟 + pcall 失败重试（3s×5）实测可靠。

【7】约束与风险
- 强转 Window：入口类必须继承 Window；Activate() 会真实弹窗，正式版改隐藏窗口或纯服务。
- Lua 侧 ok=true 不代表建成（Type.GetType 失败时异常被官方事件系统吸收），验证靠 C# 侧探针日志。
- 引擎版本目录随 api 版本区分，编辑器升级覆盖后注入失效 → 与 slots 同生命周期，重新「应用补丁」即可。
- 杀软风险低：纯托管无签名 dll、无注入技术、宿主自身加载器正常加载；监听 127.0.0.1 不触发防火墙提示。

需求7：编辑器内 HTTP 服务（外部 AI 控制调试，纳入本版）
- 依据：C# ↔ Lua 双向事件桥已核实（doc/research/csharp-module-injection.md §9）：C# EventManager.SendEvent(string,string) → Lua register_event 收；Lua MainFrame:SendEvent → C# EventObject.SubscribeToEvent 收，均支持任意字符串事件名。
- C# 侧：BridgeWindow 激活后启动 HttpListener，绑定 127.0.0.1（默认端口 39177，被占则 +1 重试至 39187，实际端口写 <运行根>/logs/bgd_csharp/port 文件并记日志）；后台线程处理请求，SendEvent 前切回 WinUI/UI 线程（DispatcherQueue）。
- 生命周期：服务随编辑器进程存亡（进程内线程，无外残留）。订阅原生 Event.ExitEditor 做优雅停机：停 listener、删除 port 文件；外部调用方连接失败即视为「编辑器不在线」（port 文件可能陈旧，以连通性为准）。
- 协议：HTTP POST JSON-RPC 风格 `{id, method, params}` → `{id, result|error}`。首版方法：
  - **call_command（通用透传，核心）**：params {name} → Lua 侧 window_title_bar.call_command(name)——官方已注册 80+ 命令一次全覆盖（'调试/调试'、'调试/停止'、'文件/打开'、'文件/新建'、'文件/保存'、'文件/保存数编'、'文件/强制重新加载项目'、'调试/再次调试上次调试版本'、'调试/调试(本地服务器)'、'发布/发布项目' 等，清单见 doc/research/editor-debug-control.md）
  - **list_commands**：返回当前已注册命令名列表（Lua 侧 wrap window_title_bar.register/register_command 记录命令表实现）
  - 常用糖：start_debug / stop_debug / get_status（{ map_open, map_path, debugging（GamePlayInEditor 槽位）, port }）
- 请求-响应闭环：C# 发 cmd 带自增 id，订阅 'bgd_mcp_ack' 按 id 匹配，超时（如 30s，启动调试较慢）返回超时错误。
- 错误处理：Lua 侧全程 xpcall，错误文本经 ack 回传；弹窗抑制见需求10。

需求8：MCP 服务直接内置于 C#（无外部进程）
- 在同一 HttpListener 上增加 `/mcp` 端点，实现 MCP **Streamable HTTP** 传输（单端点 POST/GET，JSON-RPC 2.0，System.Text.Json 手写协议层即可，零新增依赖）。
- tools/list 暴露与需求7 对应的 tools（call_command / list_commands / start_debug / stop_debug / get_status）；tools/call 映射到同一分发器（与 HTTP JSON-RPC 共用核心）。
- 支持 initialize / notifications/initialized / ping 等基础握手；resources/prompts 首版返回空。
- 取舍说明：放弃「外部 stdio 薄壳进程」作为主路径——MCP Streamable HTTP 已被主流 AI 客户端支持，直连 URL 即可；stdio-only 客户端的 shim 留作后续可选。

需求9：BridgeWindow 自隐藏（纯后台服务）✅（2026-08-16 实测通过）
- 宿主无条件 Activate() 我们的窗口 → ctor 订阅 Activated 事件立即 `AppWindow.Hide()`（需引用宿主 microsoft.interactiveexperiences.projection.dll，已验证编译通过）。
- 实测：重启编辑器后窗口不残留可见，探针日志写入 'hidden-mode test' 行（pid 实证）。
- 窗口仍保留一个「服务状态」内容页（手动再激活时可查看端口/请求计数），但不主动显示。

需求10：错误弹窗抑制与文本回传
- Lua 侧 wrap `require 'ui.components.message_window'` 的 message_window 函数（模块级单点，官方所有弹窗都经此）：受控开关（默认关，start_debug 等 AI 驱动流程期间开启）。
- 抑制开启时：不弹窗，自动以默认 opt（Close/Confirm 优先级策略）回调原流程，同时把 {title, prompt, btn_text} 经 'bgd_mcp_event' 推送给 C#（外部可取到错误文本）。
- 兜底：C# 侧订阅原生 Event.ShowMessageBox 事件感知弹窗发生（Event 枚举已核实含此值）。

需求11：原生事件推送（编辑器 → 外部）
- C# 订阅 ApplicationExport 原生事件（Event 枚举已核实：Update / E_LoadMap / CreateModule / ActivateWindow / ExitEditor / UpdateProgress / ShowMessageBox / NotifyCSharpTriggerEditor / AnimationEditorShow / CreateNewProfiler / MaterialEditorShow）。
- Lua 侧业务事件（EVENT.pie_will_launch、load_map_done、save_map 等）经事件桥转发给 C#。
- C# 维护带序号的环形事件缓冲（如 1000 条），对外提供 `GET /events?since=<seq>` 增量拉取；MCP 侧同名 resource/notification 暴露。
