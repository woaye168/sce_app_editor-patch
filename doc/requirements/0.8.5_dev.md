## 2. 概念体系（四个概念）

| 概念 | 定义 | 判据 |
| --- | --- | --- |
| **Page（界面）** | 唯一一等结构单元 = 名字 + PageType + 生命周期。**一切需要显示的东西都落到 Page** | 有类型归属和生命周期 |
| **Widget（控件）** | 可复用组合单元，只能活在 Page 的 render 内（或另一 Widget 内）。**无子概念**——不分叶子/控件/复合件/内置件/游戏件，统称 Widget | 能嵌进任何 Page |
| **Box（容器）** | Widget 的排布特例：只负责子元素的位置与流式排布，无交互语义 | 只摆位置 |
| **Cross（横切服务）** | 非结构能力：浮层/状态/投递/数据/样式/指针/查询/逃生口 | 不属于结构体系 |

**命名纪律（全库全文档执行）**：
- 概念词只有 Page / Widget / Box / Cross；禁止 layer/层/Layout/Level 等旧词；
  `panel` 一词退役（模块、API、事件名全改）。
- PageType 的数值 = **档位**（渲染上下次序的数值区间，档位容量 10000）。
  注意：档位与 RMGUI 的「绑定（bind）」无任何关系——bind 是数据通道概念，
  档位只是渲染序分带；文档一律写「档位」，不写英文以免与 bind 混淆（评审②）。

## 3. Page 定义（唯一结构）

```lua
cg.page({
    name = 'gm',                  -- 必填，字符串，全局唯一；**页名规范：小写下划线**
                                  -- （'gm'/'shop'/'loot_banner'；页名 = 视图名 = cgui id
                                  -- 路径首段 = find_ui scope，旧大驼峰模块名废弃）
    type = cg.PAGE.POPUP,         -- 必填，cg.PAGE.* 枚举值（只收整档枚举，见 §3.2）
    render = function(params) end,-- 必填。打开期间每帧执行；params = open 透传
    -- 生命周期钩子（全部可选，触发路径审查见 §3.3）：
    on_init  = function() end,          -- 首次 open 前恰好一次（懒初始化：重资源/订阅）
    on_open  = function(params) end,    -- 每次打开一次（恢复/刷参不重放）
    on_close = function() end,          -- 每次关闭一次
    -- 特性字段（全部可选；默认值来自 PageType，见 §3.1；任何类型都可显式组合覆盖）：
    queue     = true,                    -- 同类型单例排队补位
    exclusive = true,                    -- 同类型 exclusive 页互斥（语义见 §3.2）
    backdrop  = true,                    -- 全屏遮罩 + 输入吞噬（或 { color, opacity }）
    suspend   = { cg.PAGE.HUD },         -- 打开期间挂起的 PageType 集合；false = 不挂起
    group     = 'equip',                 -- 页组标记（批量操作目标，见 §3.4）
})
```

- `def` 只认以上白名单字段；未知字段 warn_once（防拼写漂移）。
- 重复注册 = 替换定义、保持当前开关状态；**重注册不重置 on_init**（on_init 以
  页生命周期计「恰好一次」；构建热重载重注册是常态，重置会导致重复订阅/
  重复加载）；open 未注册 Page = warn。
- **特性字段对全部类型合法**——没有「族字段校验」；PageType 只决定默认值
  （评审①：类型给默认特性，定义里组合覆盖，易用且灵活）。

### 3.1 PageType 与默认特性矩阵（每条规则附白话说明，答评审④）

`cg.PAGE` 注册表（值 = 档位起点；渲染序与 root_z 同源）：

| PageType | 值 | 默认 queue | 参与 back | 语义 |
| --- | --- | --- | --- | --- |
| `MAP` | 100 | 否 | 否 | **地图层**：瓦片地图/地形整层渲染（Tiled 运行时未来宿主，见 §10） |
| `WORLD` | 10000 | 否 | 否 | **地图 UI 层**：基于地图坐标定位的 UI（角色 spine/血条/掉落/飘字），跟随摄像机；**视口外不渲染优化**责任在本类型（见 §10） |
| `HUD` | 20000 | 否 | 否 | **常驻主界面**：玩家状态/功能入口，不跟随地图坐标 |
| `POPUP` | 30000 | 否 | 是 | 弹窗：多个共存，新开的在上面 |
| `DIALOG` | 40000 | 是 | 是 | 模式窗口：单例，排队补位 |
| `SYSTEM` | 50000 | 是 | 是 | 系统模式窗口：同 DIALOG，档位更高 |
| `NOTIFY` | 60000 | 否 | 否 | 消息提示：toast/播报（瞬态反馈不被挂起） |
| `GUIDE` | 70000 | 是 | 否 | 新手引导：单例，排队补位 |
| `BENCH` | 90000 | 否 | 否 | 调试台：永远在业务 UI 之上；打开时自动挂起业务档位（内建） |

**规则详解**：

- **MAP / WORLD 分层理由（评审③）**：瓦片地图整层渲染量大、渲染模型特殊
  （tilemap UV 裁剪 + 视口裁剪），且未来 Tiled 完整运行时以此为宿主；
  地图 UI（血条/飘字/spine）需要地图坐标换算 + 视口外不渲染；HUD 不跟随
  地图坐标。三者优化策略与坐标语义不同，必须分档。WORLD 启用原
  「10000~19999 死档」——死档自此不存在。
- **queue 默认**：DIALOG/SYSTEM/GUIDE = true（模式窗单例是游戏 UI 通例），
  其余 false。单例语义：同类型同时只显示一个，后开的排队，前者关闭后
  自动补位弹出。
- **exclusive 默认全 false**。语义（v2 修订，见 §3.2）：打开时关闭**同类型
  其它带 exclusive 的页**；非 exclusive 页不受影响。
- **backdrop 默认全 false**。`= true` 时框架在 render 前绘制全屏半透明遮罩
  （默认 `#000000` 不透明度 0.5；`= { color, opacity }` 可覆盖），遮罩吞噬
  全部输入（下层不可点）；页挂起时遮罩随视图整体消失。与 exclusive 正交：
  exclusive 管「同类型互斥」，backdrop 管「视觉遮罩 + 输入吞噬」。
- **suspend 唯一默认规则**：`exclusive = true` 且自身档位 > HUD 档 → 默认
  `{ cg.PAGE.HUD }`（全屏独占页打开期间 HUD 不渲染、也不可被 AI 操作，
  R2.1 语义继承）；显式 `suspend = false` 关闭该行为；显式数组覆盖集合。
  白话：全屏商店打开时，背后的主界面按钮既看不见也点不到（包括 AI）。
- **back 导航**（`cg.page.back()` 关闭最近打开页）只作用于
  POPUP/DIALOG/SYSTEM——返回键语义只对弹窗类有意义，由类型固有，不开放覆盖。
- **z 合法量纲**（check_z 校验，warn_once）：MAP 页内元素 z 0~9999 /
  类型档 X0000（type 只能是枚举值本身）/ 浮层 100000+（Z 注册表）。
  档内偏移写法（`POPUP + 100`）**已废除**（§3.2）。

### 3.2 exclusive 新语义与档内偏移废除（评审⑤，实库审查结论）

**审查**：档内偏移（`POPUP + 100`）在全库的唯一真实用途 = TeamHUD 挪到
POPUP+200 以躲开商店/背包（POPUP+100）的 exclusive 互斥（原 P2-16）。
同档叠放次序本就由 open_seq 微增量自动管理（新开在上），无需手工偏移。

**结论：档内偏移废除**，配套 exclusive 语义修订：

- 旧语义：exclusive 页打开时关闭**同精确档位全部**其它页（逼出档内偏移）；
- 新语义：exclusive 页打开时关闭**同 PageType 其它 exclusive 页**；
  非 exclusive 页不参与互斥（TeamHUD 这类共存小窗声明为非 exclusive 即可，
  无需任何偏移）；
- `type` 只接受 `cg.PAGE.*` 枚举整档值；传算式偏移 = check_z 告警非法；
- 挂起匹配随之简化为精确档值（原 band_of 双写匹配退化为单写，实现细节）。

### 3.3 生命周期（全类型统一；答评审⑥）

- **「注册后一律 closed」= 直接不显示（B 方案）**：注册只登记定义，不挂载、
  不渲染、零每帧开销；`cg.page.open(name, params)` 才挂载显示。现状
  panel.register 本就是 B（open=false 初始），直接继承；老的「mount 即常驻」
  路径废除。常驻型 Page（MAP/WORLD/HUD/NOTIFY/BENCH 业务页）在启动编排区
  （GameScene.Init / client/init.lua）统一 open 一次。
- **钩子清单与触发路径**（实码审查结论，无多重触发）：
  | 钩子 | 触发时机 | 不触发的路径 |
  | --- | --- | --- |
  | `on_init` | 首次 open 前恰好一次（懒初始化：重资源加载/协议订阅） | 后续 open 不再触发 |
  | `on_open(params)` | open 正常路径 / 队列补位路径，各一次 | 已 visible 重复 open（仅刷参）；挂起恢复；挂起态重复 open |
  | `on_close()` | close 且此前 open，一次 | close 未 open 的页（幂等返回） |
- `toggle(name, params)` 只是 `if is_open then close else open` 的单路径分发，
  与 open/close 钩子**不会重叠多重触发**（逐路径核实：toggle→close 走标准
  close 一次；toggle→open 走标准 open 一次）。
- **on_suspend/on_restore 评估后不加**：挂起 = 不渲染，tween/动画自停；
  音效类副作用由 on_open 触发、挂起不重放已够。无真实业务场景，奥卡姆
  （未来出现场景再加，语义位置预留）。
- `close_all(type?)` / `close_group(name)` / `is_open` / `is_visible` /
  `is_queued` / `list()`。
- 事件（评审⑥）：`cgui.page_opened` / `cgui.page_closed`
  （旧 `cgui.panel_opened/panel_closed` 删除；grep 证实零业务消费方）。
- **释放与状态恢复（评审⑧，现状模型确认保留并文档化）**：
  closed/suspended = 视图卸载，**渲染管线零每帧开销**（完全释放）；
  状态恢复两条通道——① 页面级状态 = 模块局部表（业务自持有，天然不丢）；
  ② 控件级状态 = `remember` 持久槽位（tab/滚动位置/草稿）。
  已知边界：非持久 remember 槽位在视图卸载 600 帧后回收（原 P2-17），
  要「关再开不丢」的状态一律走持久槽位或模块局部表。

### 3.4 页组 group（评审⑦：with 废弃，思想实验结论）

**with（声明式联动）废弃理由**：它是隐藏控制流——open/close 互相引用在
声明层不可见，动态开出的页（点物品开出的信息页）不在静态 with 列表里
覆盖不到，「关装备全关」场景恰恰覆盖不了；一级联动限制又会引出
「为什么 C 没跟着关」的怪 bug。用户直觉正确。

**替代设计 = 成员标记 + 显式批量操作**（控制流在业务手里，无隐式联动）：

```lua
cg.page({ name = 'equip', type = cg.PAGE.POPUP, group = 'equip_flow', ... })
cg.page({ name = 'bag',   type = cg.PAGE.POPUP, group = 'equip_flow', ... })
-- 信息页（点物品动态打开）同样标记 group = 'equip_flow'

cg.page.open_group('equip_flow')   -- 批量开（按注册序）
cg.page.close_group('equip_flow')  -- 批量关（幂等，无循环可能）
```

装备场景落地：HUD 入口 `on_click` → `open_group('equip_flow')`（或只开
equip+bag 两个）；装备页关闭按钮 `on_click` → `close_group('equip_flow')`——
动态开的信息页也在组内，一并关闭。group 可多重归属不开放（一组一词，
保持心智简单；确有多组需求时业务在钩子里组合调用）。

### 3.5 root_z / 渲染序（框架自动，业务不可传）

渲染序 = 档位值（+open_seq 微增量，同类型新开在上）；root_z = 档位值。
`def` 不接受相关字段（传了 warn_once 忽略）；`core.check_z` 框架侧继续生效。
**路径推导删除（评审⑲，奥卡姆）**：type 必填，不从文件路径推导，不做路径
一致性告警；`LAYER_NAME`/layer_resolver/consistency_checker 机制全删。
目录（page/<类型名>/ 等三种形式）只是仓库组织推荐。

### 3.6 旧 API 映射（不留兼容）

| 旧 | 新 |
| --- | --- |
| `cg.panel.register(name, draw, opts)` | `cg.page({ name, type, render, ...特性 })` |
| `cg.panel.open/close/toggle/back/close_all/is_*/list` | `cg.page.*` 同名 |
| `cg.mount(name, draw, { order, root_z })`（业务常驻视图） | `cg.page({ name, type, render })` + 启动编排区 `cg.page.open(name)` |

## 4. Widget 调用约定

**总则一句话：props 表在前，children 闭包在后。**

心智模型（答 v2-⑨）：**调用即绘制**。立即模式下每次 `cg.xxx(...)` 调用 =
在组合流的该位置放置一个元素；无参组件也要调用——`cg.divider()` 就是
「在这里画一条分隔线」，props 省略只是因为该组件没有需要配置的东西。
Box 无 props 时 children 提为唯一参数：`cg.fullscreen(function() ... end)`。

1. 调用形态只有两种：`cg.xxx(props)` / `cg.xxx(props, children)`（children 为无参函数）。
2. props 字段五组（按此顺序记忆）：
   - **key**：身份。同级唯一；省略按调用位置自动编号（@1@2 机制不变）；
     动态列表/条件分支必须显式 key。取代旧 id 参数与 id_or_opts 重载。
   - **tag**：语义检索标记（评审⑧ 约定）：`tag = 'shop_list'` 单标记或
     `tag = { 'shop_list', 'currency' }` 多标记（任一命中即匹配）；
     可重复、可跨控件相同；命名小写下划线。与 key 的区别：key 管身份唯一性
     （框架对位用），tag 管语义检索（AI/调试找 UI 用）——沉淀进 dbg 快照，
     find_ui 按 tag 过滤、取 rect 供 capture crop 局部截图（§8.3）。
     Page 不需要 tag——Page 名即身份（scope 参数）。
   - **数据**：组件内容输入（text/value/items/selected/...）。
   - **回调**：on_xxx（见 §4.1 命名表）。widget 层剥离后再进 core——
     「回调勿进引擎 props」护栏语义不变，剥离点移到 widget 层。
   - **覆盖**：layout/font/color/...（与样式段深合并、优先级最高，机制不变）。
3. **句柄返回是 Widget 通用能力**（评审⑱ 泛化）：任何 Widget 可返回稳定身份
   句柄/查询接口（joystick 的 vec、pscroll 的 scroll_to 是实例）；句柄跨帧
   稳定，每帧调用零额外成本。
4. Box 清单（有 children 第二参的完整集合）：flow/grid/cell/stack/scroll/pin/
   center/fullscreen/window；Widget 中带 children 的：form_row/cooldown/drag/
   drop_target/drag_ghost；Cross 逃生口 raw。除此之外一律单 props。

### 4.1 回调命名表（评审⑨：子代理全量分析后定稿；函数字段一律 on_ 前缀，禁止发明新名）

**A. 手势事件（指针交互）**

| 回调 | 语义 | 引擎来源 |
| --- | --- | --- |
| `on_click()` | 左键点击（按下+抬起同元素） | on_real_click==1 |

## 6. 状态服务重构（评审⑭②/⑮b，具体设计细节）

**remember / tween**（key 自动编号，机制现成——remember 槽位身份 = 控件
路径 + key，key 复用调用位置自动编号）：


  `cg.tween(target, { key?, duration?, easing?, speed?, anchors?, path_start? }?)`；
  **实现先入库、cg 绑定在 T6.0 统一切换**（新旧签名无法可靠重载共存——
  initial 与 key 撞型；见 §8.4 双轨纪律）；

### 8.3 tag + scope 检索（评审⑩ + v3 实况修正，新增能力）

- **tag**：Widget props `tag`（string 或 string[]，任一命中即匹配）→ widget 层
  剥离 → core.begin 存 frame.tags → dbg.on_finish 沉淀 entry.tags → find_ui
  支持 tag 过滤参数并返回 tags；
- **scope**（名实相符的真参数）：find_ui 增加 `scope` = 页名前缀过滤
  （id 路径首段匹配，如 `scope = 'shop'` 只查 shop 页的控件）——比 q 子串
  匹配快且无歧义；Page 名即 scope 值，页级检索不需要 tag；
- AI 精准区域截图动线：find_ui（scope/tag/文本）拿 rect → capture_game
  crop=rect；
- 改动面：core/dbg/dbg_commands + sce_app_editor-patch 桥 lua.find_ui 加
  scope/tag 参数（均可选，前向兼容）。

### 8.4 切换纪律（评审⑳ + v3/v4 双轨扩展：不中断、不改自闭）

**双轨对象 = page 内核 + widget 库 + 状态服务绑定**。核心规则：**cg 表上的
一切签名变更（widget 组件 + remember/tween）都归属同一个切换点**——
新旧签名无法可靠重载共存（remember 的 initial 与 key 撞型；col/row/box
新旧同名不同义），cg 表只能绑一套。

1. **T1/T1b** `cgui/page.lua` + backdrop（panel.lua 并存不动；cg.page 新增
   暴露，与 cg.panel 不同名无冲突）；
2. **T2** 新建 `libs/client/widget/` 新签名库，旧 `cgui/widget/` 原样并存；
   **T3** remember/tween 新签名实现入库（**cg 绑定不切**）+ tag/scope/raw
   （纯新增零破坏）；
3. **T4/T5** 框架 Page 用新库写：模块级 `require('libs.client.widget.xxx')`
   直调新签名（cg 表此阶段仍绑旧库）→ 真机验证全绿（**第 1 步全绿点**，
   仪器常绿是后续排障的前提）；
4. **T6 原子切换批**：**批首 T6.0** 一次性把 `api/cgui.lua` 的 cg.* 切到
   新库（含 remember/tween 绑定）——切换后游戏旧 UI 暂时全坏属**批内
   中间态**（「不中断」= 每批结束系统可用、仪器常绿；批内逐页迁移恢复
   正是本批本职）；**迁移页直接写 cg.* 终态**（与 §11 模板一致，无模块级
   过渡形态、无二次改写）→ 批末真机回归全绿（**第 2 步全绿点**）；
   T6.9 收尾把 T4/T5 框架页的模块级 require 顺手统一为 cg.*；
5. **T7** src_template 同步——**必须先于 T8**（模板在用 cg.patterns.form_page
   与 cg.panel.register + 目录推导，删除瞬间模板即坏）；此时 cg 已切新，
   模板直接用 cg.* 终态写；
6. **T8** 全绿后删除：panel.lua、旧 cgui/widget/、patterns.lua、kit.register、
   旧事件名、路径推导机制、col/row/box 旧名、档内偏移写法、旧 state 形态；
7. editor-patch 侧（find_ui scope/tag 参数）最后配套，可选参数先行，
   游戏侧就绪后启用。

## 9. 性能红线（评审⑱ 查漏补缺后定稿）

- render 每帧执行：帧内小表/闭包分配是约定形态（props 签名去重保证引擎侧
  零重放、保 input 焦点）；**禁止**在 render 内做：大表排序/过滤等重计算
  （提到状态变更处缓存）、IO、require。
- 大列表必须 vlist/vgrid（虚拟化），禁止全量 for 渲染。
- 图集渲染走 tileset/tilemap（sprites UV 裁剪不占 clip 槽池；clip 预算 400）。
- MAP 页整层瓦片 = tilemap 视口裁剪；**WORLD 页元素视口外不渲染**（culling
  责任在业务/运行时：世界坐标 − 摄像机后超出视口即不画，现算现绘天然支持；
  框架提供 view_size 查询）。
- Page 关闭/挂起 = 视图完全卸载，零每帧开销；toast/dialog 页常驻空 render
  早退（空队列一次判断，成本可忽略）。
- tag 仅 dbg 开启时沉淀（惰性，零常驻开销）；Widget 注册表只存元数据。
- 句柄型 Widget 返回稳定身份句柄（§4.3 通用能力），每帧调用零额外成本。
- 统一 Page 不新增每帧开销：注册表即现 panels 表演进，tick 管线不动。

## 10. MAP/WORLD 与 Tiled 运行时预留（评审③⑲）

**本期落地**：游戏 `src/client/ui/world/` 现有模块按新分层重写（实战验证
新架构，同时为 Tiled 运行时铺路）：

- `page/map/MapView.lua`（type=MAP）：瓦片地图/地形整层渲染（MapRender 的
  渲染部分迁入）；
- `page/world/`（type=WORLD）：实体/血条/掉落/飘字/黑幕（RemotePlayers/
  Effects/FieldObjects/PlayerLife/HpBar 等），地图坐标定位 + 视口 culling；
- 两页各自独立的页内 z 空间（拆分红利：不再与世界带 0~9999 混排）。

**未来预留（本期只定接口形态，不实现）**：`libs/client/tiled/`
（`bgd_api.client.tiled`）——Tiled 地图加载/瓦片渲染/视口裁剪/摄像机/
碰撞查询；内部注册 `type = cg.PAGE.MAP` 的 Page 作渲染宿主；游戏特有世界
元素留在游戏 WORLD 页（同类型多页共存，按 open 序叠放）或经 tiled 渲染
钩子按 z 挂入。src 现有 world 模块是其雏形与迁移素材。

```lua
-- src/client/page/popup/GMUI.lua
```

```lua
-- src/client/page/notify/LootBanner.lua
-- NOTIFY：瞬态反馈；默认不被挂起（toast/播报挂起会吞消息）
local protocol = require('libs.common.api.protocol')
local P = require('src.common.Protocol')

local cg = bgd_api.client.cgui

local HOLD = 5
local QUALITY_COLOR = { epic = '#B15CFF', legendary = '#FF8C00' }
local queue, current, show_until = {}, nil, 0

protocol.on(P.Sync_LootAnnounce, function(data)
    queue[#queue + 1] = data
end)

cg.page({
    name = 'loot_banner',
    type = cg.PAGE.NOTIFY,
    render = function()
        if not current and #queue > 0 then
            current = table.remove(queue, 1)
            show_until = os.clock() + HOLD
        end
        if current and os.clock() > show_until then current = nil end
        if not current then return end -- 无播报 = 不画（调用即绘制的反面：不调用即不显示）

        cg.pin({ anchor = 'tc', offset = { 0, 120 } }, function()
            cg.flow({ direction = 'row', tag = 'loot_banner', color = '#1A1A2ECC',
                round_corner_radius = 8,
                layout = { padding = { left = 16, right = 16, top = 8, bottom = 8 } } }, function()
                cg.text({ text = string.format('玩家 %s 爆出极品装备【%s】！',
                        current.player, current.item),
                    font = { size = 20, bold = true,
                        color = QUALITY_COLOR[current.quality] or '#FFD700' } })
            end)
        end)
    end,
})

end
```
