## 第二轮（用户实战反馈，2026-08-18 凌晨）

用户经 MCP 让 AI 打开触发编辑器后退出，弹「发生异常：`String` 不能转 `System.Int32`」。

- **根因**：AI 客户端把数字参数传成字符串（如 `timeout_ms:"5000"`），Bridge 内「`GetValue<int>()` 抛了再 catch」式防御解析在注入进程内等同于弹窗——**编辑器对 first-chance 异常（即使被 catch）弹模态**，而静默 catch 又让桥日志无任何记录（用户的两个疑问点同因）。
- **修复**：新增 `JsonRead` 零异常宽容读取（ValueKind 预判 + TryGetValue，数字字符串自动兼容，非法类型回落默认并记 WARN），替换 Gateway/McpServer/Executors 全部 AI 可控参数的异常式解析；新增 N-1/2/3 回归用例。
- **验证**：字符串参数正常宽容、非法类型记 WARN「参数 timeout_ms 类型不符（Object），用默认值 5000」、编辑器异常日志零增长、无弹窗。
- **测试覆盖说明**（用户问题 1）：此前未全量调用 112 个 cmd.* 菜单命令（多数有 UI 前置状态、盲调有破坏性）；本轮把防线收敛到「任何入参形态都不产生 first-chance 异常」，cmd.* 通道本身只是 fire-and-forget 转发菜单事件。

## 修复的 Bug（5 个）

### 1. 端口占用误报（用户报告的主 Bug）
- **现象**：启动编辑器必报「端口 39177/39179 被占用」，换端口无效，netstat 查不到占用进程。
- **根因**：Hyper-V/WSL/winnat 动态保留 TCP 端口段（本机 `39173-39272`，`netsh int ipv4 show excludedportrange tcp` 可见），段内端口任何进程绑不上，HttpListener 报 ERROR_SHARING_VIOLATION，与「进程占用」错误文案完全相同，极具迷惑性；保留段每次开机动态变化。
- **修复**：McpServer.Start 启动时探测系统保留段；配置端口在段内或被占时自动向后避让（最多 100 候选），实际端口写 port 文件 + WARN 日志。P0-1（保留段避让 39177→39273）/P0-2（段外 41801 直绑）/P0-3（真实进程占用 41801→41802）三场景实证通过。

### 2. datacore 写路径约定错误
- **根因**：`DataCore.AddGameChange` 内部固定定位 `IsMatchKey("Game")` 顶层 pair，写路径必须相对 Game 对（官方 PlayerSettings 传 `["player_setting"]`）；实现与 annotations 示例都带了 "Game" 前缀 → AddGameChange 必返 false。
- **修复**：执行器剥掉首段 "Game"（读写路径风格保持一致）。

### 3. DataDecimal 封送必炸（引擎侧 Bug 绕行）
- **根因**：`DataDecimal.ChangeValue` 把 decimal 直传 P/Invoke，`DataValMarshaller` 封送白名单不含 decimal → 必抛 InvalidDataException。原「MakeInt 失败 fallback MakeDecimal」等于fallback 到必炸路径。
- **修复**：自实现 `DataDouble : IDataType`（double 在白名单内）；小数写入与 int 重试均改走 DataDouble。

### 4. 文本字段写失败
- **根因**：Name 等多语言文本字段需 `MakeText`（ENSVM_PASTE + Default 子键），MakeString 直写返回 false。
- **修复**：字符串值写入失败时自动 fallback MakeText（write/batch_write 均覆盖）。

### 5. 业务异常触发编辑器「发生异常」模态 → 全链路超时
- **根因**：编辑器对 first-chance 异常记 `logs/CSharp/Exception/` 并弹模态（即使异常被 catch）；模态期间 BridgeWindow DispatcherQueue 不泵，所有 svc/datacore 调用连锁超时。
- **修复**：datacore 执行器业务错误一律返回 `{ok:false,code,message,hint}` 错误节点（ErrNode），零异常；UiToOp 把错误节点作为 error 透出（顺带修复了 batch_write 失败时 `error:null` 的响应缺陷）；UiThreadInvoker 超时后观察掉队任务，消除 finalizer UnobservedTaskException 噪音。

## R2 实证（M4 前置项）——结论：不可撤销

`datacore.write`（auto_commit=true）提交 opened_slots=[9] → UndoRedoManager can_undo=true → undo 至栈空（3 次）→ 回读仍 [9]。**CommitChanges 不进 undo 栈，Ctrl+Z 不可撤销**。按 0.5.0 预案定稿：write/batch_write auto_commit 默认改 **false**、写类升 **danger** 级；文档已回填 survey §6.2 与需求文档。
