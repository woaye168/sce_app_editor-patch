# 0.8.1 需求与方案：cgui 内生 AI 可驱动 + 虚拟指针 + 场景脚本进化

> 状态：**讨论稿，待评审**
> 背景：0.8.0 验收（CGUI 调试台全功能扫描）中暴露三个层面的问题，对应三条需求线。
> 本文每个结论都附实测依据（0.8.0 验收现场 + 源码验证）。

## 三条需求线的由来与分析

### 点 1：AI 编写完整 UI 测试的成本太高（亲历实测）

0.8.0 验收时，AI 为「把调试台所有功能点一遍」编写了 bench_sweep.ps1，过程暴露了真实痛点：

| 痛点 | 实测现场 | 根因 |
| --- | --- | --- |
| 静态 id 未知，先 find 再拼场景 | wc_type/kit_* 路径反复 find_ui 探测 | run_scenario 步骤间无数据传递 |
| find→click 链式操作无法表达 | 「找文本→拿 clickable_ancestor→点」要 2~3 次往返 | 缺复合命令 |
| 下拉操作定式要背 | find 命中根面板不可点，得点 `<id>/anchor`，菜单项在 `overlay/dropdown_list/<N>` | 知识在文档里，不在工具里 |
| 入口 toggle 状态未知 | hub 入口是开关，盲点会反关 | 缺「确保态」语义 |
| 断言靠截图后人工看 | 验证「点了确定」要再 find 一次文本 | 缺 assert 步骤 |
| MCP stdio 进程中途死亡 | 验收中途 CONNECTION_CLOSED，进程消失 | **不是 --quit 误杀**（stdio 走 run_stdio 独立路径，不经 appsdk watcher）；真因 = run_scenario 步骤截断按字节切在多字节字符中间 panic（`end byte index 2048 is not a char boundary`，「点」横跨 2047..2050），0.8.1 已修复并加单测 |

### 点 2：「开发者要背 MCP 契约」是设计气味（架构层面）

0.8.0 的 cgui_mcp.md 契约要求新 widget 作者记得 `dbg_register`——**这正是该消除的负担**。
源码实测发现关键事实：**主路径本可以不需要注册**：

- 点击已对「读 state() 的控件」零注册可用（state 注入兜底，bench 手写菜单/部件列表全是这么点动的）；
- `input` 控件读的是 `st.on_input` 字段（control.lua:677）——**直接注入该字段即可，无需注册回调**；
- slider/joystick 读 `st.drag` + 指针位置——可注入（见点 3）；
- `dbg_register` 真正的价值只剩两个：① callback 直调当**加速/同步返回**的优化路径；② 摇杆这类「持续向量模拟」的特化。

**结论：把「状态注入」从兜底升级为主路径，注册降级为可选优化**——新 widget 作者（人或 AI）
什么都不用记，控件只要读了 `state()` 就自动获得全部 MCP 交互能力。契约文档从
「接入纪律三条」改写为「零接入说明」。

### 点 3：hover/滚动/拖拽缺口 → cgui 层虚拟指针

0.8.0 遗留：hover 不可模拟（引擎 imgui 输入是拉取式，脚本层无注入 API）。
但 state 字段实测可读可写（注入正是靠克隆 st 覆写字段生效），完整字段面
（types/class_imgui.d.lua:202-229）覆盖：hover/on_mouse_enter/leave、press、
on_mouse_down、on_real_click、drag/on_drag_begin/end、on_scroll/scroll_range、
on_input、drop_hover/on_drop——**cgui 层可以实现一只「虚拟指针」**：

- dbg 快照已有每帧全控件 rect → cgui 自己做命中测试（倒序取顶层 = 绘制序近似 z 序）；
- 虚拟指针状态 `{x, y, down, drag_from}` 驱动每帧 st 字段注入：悬停/按下/拖动/抬起/滚动；
- 关键收敛点：`core.pointer()` 已是框架缓存指针位置的约定入口（core.lua:268「业务/组件一律走
  M.pointer*」），但 slider（control.lua:570/586/591）和 joystick（joystick.lua:116/124）
  **违规直读 `base.screen:input_mouse()`**——需先收敛，虚拟指针才能一处生效。

滚动补充实测结论：引擎 scroll 容器 `scroll_pos` 写入不生效（pscroll.lua:4 注释实锤），
但框架自有 **pscroll 受控滚动容器有 `scroll_to(y)` 程序 API**——滚动覆盖走
「pscroll 注册 scroll_to 句柄」+「引擎 scroll 容器建议业务迁 pscroll」双轨。

与点 2 的关系：点 2 完美落地后 AI 已能操作全部标准控件；点 3 的虚拟指针补上
hover/滚动/拖拽/长按等**时序型交互**（背包下滑、拖放排序、tooltip 验证、摇杆拖动），
两者合起来 = 完整游戏模拟。

### R1 cgui 内生可驱动（点 2，认知负担归零）

| 子项 | 内容 | 依据 |

### R2 虚拟指针（点 3，时序型交互）

dbg.lua 升级为虚拟指针子系统（不新增模块，dbg 本就是调试反射职责）：

| 子项 | 内容 |
| --- | --- |
| R2.1 | **指针收敛**：joystick/slider 等直读 `base.screen:input_mouse()` 的控件改走 `core.pointer()`；core 指针更新处支持虚拟指针覆写 |
| R2.2 | **命中测试**：dbg 快照 rect 倒序命中（近似 z 序），产出目标控件 id；考虑父链 clip 交集（v1 可简化为 rect 命中 + 可见性） |
| R2.3 | **状态机注入**：vp={x,y,down} 驱动每帧 st 覆写——hover（含 on_mouse_enter/leave 沿）、down（press+on_mouse_down+on_drag_begin）、move（drag=1+指针位置）、up（on_real_click 同控件 / on_drag_end + on_drop 跨控件） |
| R2.4 | 新 MCP 能力：`lua.hover_ui {id}`（真实悬停，替换 0.8.0 的诚实报错）、`lua.drag_ui {from_id, to_id}`（拖放/排序/摇杆拖动统一原语）、`lua.scroll_ui {id, delta_y}`（pscroll 走 scroll_to 直驱；引擎 scroll 容器报 actionable 错误建议迁 pscroll） |
| R2.5 | hover 真实化验收：tooltip（kit.lua:419 `not st.hover` 才关）、slider hover 态样式、on_mouse_enter 业务回调 |

### R4 非目标（明确不做）

- 不做 Win32 级键鼠注入（0.8.0 R3 已否决：作用域失控风险 + 前台焦点依赖；cgui 层虚拟指针是纯 Lua 等价物）；
- 不做引擎 scroll 容器的强行驱动（pscroll 双轨即可）；
- 不做页面级自动巡检 sweep 命令（副作用不可控；R3 变量+断言已覆盖「写一遍完整测试」场景）；
- RMGUI 旧界面不覆盖（新 UI 唯一路径 = cgui 的既定约定再次兑现价值）。

## 架构影响面

```
MCP lua.tap/pick/hover_ui/drag_ui/scroll_ui（catalog 静态条目 + annotations 别名）
  → 桥 ui_loop.lua（薄转发，不变）
  → dbg_bus.lua / dbg_commands.lua（tap/pick 复合 + 新命令）
  → cgui/dbg.lua（虚拟指针状态机 + 命中测试 + 字段注入）
  → cgui/core.lua（pointer 收敛点支持 vp 覆写）
  → widget/joystick.lua + widget/control.lua slider（直读引擎指针 → core.pointer()）
```

文档同步：cgui_mcp.md 改写（零接入）+ cgui.md 指针约定段 + 排障笔记补虚拟指针实测结论。

## 风险与开放问题

1. **命中测试的 clip 语义**：scroll 容器内子控件 rect 可能超出可视区（裁剪后不可见但 rect 仍在）——v1 简化处理（rect 命中即可），v2 再算父链 clip 交集。
2. **注入与真实输入混用**：虚拟指针激活期间用户真鼠标也在动——调试场景可接受（PIE 专用、dbg 惰性开关），文档注明。
3. **on_drop 数据载荷**：拖放的 data 来自拖动源的 imgui.data()——drag_ui 需要在源控件按下帧读取 data 并在目标帧注入 on_drop，跨帧时序要实测验证。
4. **R3.1 变量引用 vs 步骤截断 2KB**：引用值若是大 JSON 会膨胀——约定 save_as 只存标量（id/文本/数值）。

## 验证方式（test_res002 真机）

- R1：移除 bench 页面全部 dbg_register 后重跑 bench_sweep 仍全绿（零注册路径实证）；
- R2：tooltip hover 截图验证 / 背包列表 scroll_ui 下滑截图对比 / drag_ui 拖 sortable_list 第 5 行到第 1 行后 find_ui 文本序验证 / 摇杆 drag_ui 拖动向量验证；
- R3：用新场景语法重写 bench_sweep（步骤数对比收敛，预计 ps1 百余行 → 场景 30 步内）。
