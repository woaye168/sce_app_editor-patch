# 0.6.3 需求与方案：SDK 包化 + 通用 UI + 应用市场加载优化 + 去硬编码 + README 同步

> 状态：开发中
> 承接：0.6.0 架构升级（bgd_sce_appsdk 已建立）

## R1：bgd_appsdk 改用发布的包（path → git 依赖）

- **问题**：editor-patch / visual-injector 的 `bgd_appsdk = { path = "../bgd_sce_plugins" }` 绑死本地目录结构，不可移植。
- **方案**：两应用 Cargo.toml 改为 `bgd_appsdk = { git = "https://github.com/woaye168/bgd_sce_appsdk" }`；CI 用 GH_TOKEN 配置 `git config --global url."https://x-access-token:${GH_TOKEN}@github.com/".insteadOf "https://github.com/"` 后 cargo 即可拉取私有仓库（工作流 with 里用 `${{ github.token }}`，无需另设 secret）；CI 不再需要检出 SDK 与改写 path 的步骤。

## R2：应用窗口通用 UI 抽到 bgd_appsdk

- **问题**：editor-patch 与 visual-injector 的主窗口大量重复（中文字体加载、项目栏、选项卡、日志/状态栏、窗口尺寸约定、单实例/看守线程接入模式）。
- **方案**：SDK 新增 `ui` 模块（eframe/egui 依赖）：
  - `AppShell` 壳：标题/尺寸约定 + 中文字体 + 顶部项目栏（显示当前项目 + 「选择项目…」按钮）+ 选项卡栏 + 底部状态栏，以及统一的 quit/refresh 标志轮询；
  - 应用侧实现 `ShellApp` trait（`tabs()` / `ui_tab(&mut self, ui, tab)` / `on_project_changed()` 等），只关心「有哪些标签、各标签渲染什么、项目变化做什么」。
  - 两应用接入后各自的窗口代码收敛为「标签注册 + 业务面板」。

## R3：应用页加载优化（立即显示 + 逐应用异步补全）

- **问题**：应用页整体 await 拉清单 + 逐应用补全元数据（每个一次 releases/latest + asset 下载，~1-2s/个），期间 UI 白屏且左侧菜单切换被前端逻辑阻塞。
- **方案**：
  1. 后端拆命令：`fetch_app_registry_basic`（只拉 registry raw 并播种自启默认，不含 enrich）+ `enrich_app(app_info)`（单应用补全）；
  2. 前端：进页立即渲染已安装区 + 用 registry 骨架渲染市场条目（仅 id/name），逐应用异步调 enrich 后回填版本/描述/作者/版本说明（加载失败不显示该条目，不阻塞其他条目与菜单切换）。

## R4：去硬编码编辑器路径

- **问题**：annotations.json 示例、bgd_mcp_bridge.csproj / make_catalog.csproj 的 `SceHostDir` 默认 `D:/sce_online/version-13`、tools/cleanup_smoke.ps1 默认引擎根——都是本机路径，换机器即失效。
- **方案**：
  - csproj：`SceHostDir` 默认值改为 `$(SCE_HOST_DIR)` 环境变量（无则留空并报明确错误「请设置 SCE_HOST_DIR 或用 -p:SceHostDir=... 传入」）；CI 本就显式传参不受影响；
  - annotations.json：示例路径改为通用占位（如 `D:/test/test.txt`）；
  - cleanup_smoke.ps1：EngineRoot 参数改为必填（无默认值；保持环境变量 SCE_ENGINE_ROOT 兜底）。

## R5：README 全量同步

- **问题**：四仓库 README 与现状脱节（bgd_sce_appsdk README 还是旧「应用清单仓库」描述含已废弃的 registry 字段；editor-patch README 有 bgd_sce_plugins 链接与 bump registry 的旧流程；tools README 应用市场描述滞后）。
- **方案**：四仓库 README 逐一对齐当前事实（appsdk 双职责 + registry 极简 + app-release.json 链路 + notify/联动 + 新发布流程「打 tag 即全部完成」）。

## 验收标准

1. 两应用在不含 bgd_sce_plugins 目录的环境可独立构建（git 依赖拉取）；CI 正常出包。
2. 两应用窗口代码收敛到标签注册 + 业务面板，视觉风格统一（同一壳）。
3. 应用页进页 <1s 出列表骨架；各应用条目独立回填；加载期间菜单切换不受阻。
4. 仓库内无 `D:/sce_online` 类硬编码机器路径（grep 验证，除文档叙述性示例外）。
5. 四仓库 README 与当前架构一致。
