## 0.3.1 实施理解（AGENT 确认版，已与需求方对齐）

### 一、两个 Bug 的根因与修复原则

- **需求1（script 库失败）**：库内源文件编码不统一（如 common/init.lua 是 GBK，xdeditor/main.lua 是 UTF-8），0.3.0 对入口文件做文本级改写时按 UTF-8 读取即失败。**修复原则：不再对库源文件做运行时文本改写**——插槽以「完整新源码文件」形式预制在仓库里，应用时整体复制覆盖；还原时用整库备份覆盖。字节级复制不做编解码，编码问题自然消解。
- **需求2（菜单不生效）**：hook 时机错误——menu_bar 在登录成功后的 `show_editor_main_ui()`（main.lua:473 `include 'ui'`）才加载，而插槽在 main.lua 加载期就执行，过早。**修复原则：先研究、后动手**。菜单注册的正确做法有两种：①把注册代码直接放进 menu_bar.lua 的插槽文件里（与官方注册同上下文、同时机）；②入口模块里跨文件 require 注册，但必须使用「xdeditor 库的正确机制」（通过源码研究得出，如事件/回调/正确挂载点），不靠猜。**本次迭代采用方法②**——因为它同步完成 skills 的知识沉淀（研究出正确机制 → 写入库知识库 → 后续同类补丁复用）。

### 二、0.3.1 架构（两套体系，职责分明）

1. **patches/（保持现状，独立补丁模块）**
   - 不改库源码的源文件，**版本不敏感**；可勾选、支持 default_enabled。
   - 仍是 `<库require根>/sce_app_editor-patch/` 框架目录 + AUTO-GENERATED 入口的那套。
   - 现有模块：script/hello、script/unwatch 保持；menu_bgd 从「模块 require 注册」改为「slots 插槽文件」实现（见下），对用户仍是可勾选模块的呈现（或按研究结果决定归属）。

2. **slots/（新增，仓库根目录，放「带插槽的新源码文件」）**
   - 目录组织：`slots/<库名>/<库版本号>/<按该库该版本源码目录结构安放的新源码文件>`
     例：`slots/xdeditor/160/ui/menu_bar.lua`、`slots/script/199/common/init.lua`、`slots/script/199/common/isolation.lua`
   - 文件是**完整的新源码**（官方源码 + 我们的插槽/修改），应用补丁 = 整库解密后把对应 `<库名>/<库版本号>/` 整棵树复制覆盖进库目录；还原 = 整库备份覆盖（0.3.0 已有）。
   - 天然支持：**多插槽**（同一库放多个文件）与**源文件直接覆盖**（文件即完整替换）。
   - 版本敏感是故意的：不同库版本同文件内容不同，所以按库版本建子目录。当前只维护 3 个 api 版本对应的库版本：
     | api 版本 | script | xdeditor |
     |---|---|---|
     | 12 | 185 | 142 |
     | 13 | 199 | 160 |
     | 2000 | 197 | 159 |
   - 应用时按当前库版本匹配 slots 子目录；**无匹配版本则跳过并明确提示，不蛮干**。
   - 内核入口插槽、isolation 解锁也统一改为 slots 文件实现（kernel.rs 不再内嵌文本转换逻辑，只负责：备份 → 解密 → 复制 slots → 建补丁目录）。

### 三、研究与 skills（先于需求2修复执行）

#### 3.1 研究方法论（硬性要求）

- **精确到每个库的每个源码文件**：研究成果必须覆盖库内全部源码文件（逐文件有记录），否则不足以支撑精准补丁开发。
- **使用子代理执行研究**：主会话制定研究清单，子代理分批执行，避免主上下文爆炸。
- **研究清单计划先行**：先产出研究清单（文件清单分组 + 每项研究要点），再按清单逐项执行。
- **成果即时独立落盘**：每批研究结果立刻写入独立的成果文件（不依赖会话记忆），会话中断也不丢研究进度；成果文件可断点续研。
- 所有结论标注来源（文件:行号），不臆测。

#### 3.2 skills 体系（流程技能 + 库知识库技能 两层）

库源码知识**按「库名-版本」独立成 skill 单元**，避免流程技能随库版本无限膨胀：

```
.trae/skills/
  sce-editor-patch-module/      # 流程技能：patches/ 模块开发（怎么写模块、注册、发版）
  sce-editor-lib-onboard/       # 流程技能：扩库与 slots/ 插槽开发（怎么接新库、做插槽文件）
  sce-lib-script-199/           # 库知识库：script 库 v199（逐文件研究文档 + 类型声明 + hook 配方）
  sce-lib-xdeditor-160/         # 库知识库：xdeditor 库 v160（同上）
  ...                           # 后续新库/新版本按需新增独立知识库（如 sce-lib-xdeditor-159）
```

- **流程技能**（2 个，现有）只讲「怎么做事」，SKILL.md 中链接所需库知识库；**库知识库**（按 库名-版本 独立）只讲「这个库是什么」：架构、加载流程、逐文件说明、API 类型声明、已验证 hook 点配方。
- 库知识库内部结构（每个知识库 skill 目录下）：
  - `SKILL.md`：知识库导引（何时查阅 + 文件索引）
  - `architecture.md`：库架构、加载流程、lua state 模型
  - `api.md` 或类型声明文件：关键全局/API 签名（common、base、log/log_file、EDITOR、SCE、argv、window_title_bar 等）
  - `hooks.md`：已验证的补丁 hook 点配方（如「加菜单 → 用 xx 机制，见 xdeditor 研究」）
  - `files/`：逐文件研究记录（按源码目录结构组织）
- 本轮研究范围：script-199、xdeditor-160（api 13 当前版本）；api 12/2000 的库版本知识库后续按需补。

### 四、实施顺序

1. 制定两库研究清单 → 子代理分批研究 → 成果即时落盘为库知识库（sce-lib-script-199 / sce-lib-xdeditor-160）
2. 研究中专门攻克「xdeditor 正确的菜单注册机制」（需求2 方法②依赖）
3. slots/ 架构落地（kernel.rs 改造：复制式插槽；编码问题随之消解，需求1 修复）
4. 菜单补丁用研究出的正确机制以模块实现（需求2 修复）
5. 重写两个流程技能的 SKILL.md，链接库知识库
6. cargo test / 真实项目验证 / AGENTS.md / README 同步 → v0.3.1 发版 + registry 更新
