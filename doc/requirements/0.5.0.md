# 0.5.0 需求与方案（终稿 v3）：海量工具 MCP 架构

> 状态：已评审定稿（2026-08-16，v3 并入架构评审 R1-R5 反馈：svc 服务级准入、commit 可撤销性实证、版本漂移通知、M5 量化验收、里程碑重排），待开发
> 前置研究：doc/research/mcp-capability-survey.md（CppInterface/DI 能力面勘察，本方案的关键依据）
> 兼容性说明：本项目未对外开放、无正式用户，**不做任何向后兼容**——旧机制直接替换，不留兼容层

## 需求（原始）

1. 菜单命令只是一部分。引擎还有 SCE.CppInterface.* 下大量 native 导出（DataEditor 数编读写、EventManager、Score 等）和其他托管 dll 的服务。全部可以纳入 tools
2. 返回和调用都不易读（`\uXXXX` 满屏、JSON 套 JSON 双重转义、`cmd_u6a21u5757_...` 不可读 slug）
3. MCP tools 太多，需要企业级的海量工具 MCP 架构设计

## 方案总览：Gateway + 能力目录 + 元工具搜索

放弃「每个能力 = 一个 MCP tool」模型（千级能力下必然上下文爆炸）。tools/list **恒定只暴露 ~10 个固定元工具**；全部能力进入可搜索的**能力目录（Capability Catalog）**。

```
AI 客户端 (MCP / HTTP RPC)
   │
   ▼
McpServer（Gateway，进程内 HttpListener 39177，tools/list 恒定）
   │
   ├─ 能力目录（catalog，可搜索，构建期生成 + 人工标注/别名）
   └─ 执行器路由（按能力 id 前缀）
        ├─ svc.*      → ServiceExecutor：DI 单例服务反射调用【主力通道】
        ├─ cpp.*      → CppExecutor：SCE.CppInterface 静态基元方法反射调用【次要通道】
        ├─ datacore.* → 手写高层封装：IDataCore 数编读写【手写，非反射】
        ├─ cmd.*      → Lua 桥菜单命令（现有）
        ├─ lua.*      → Lua 桥 method（现有）
        └─ sys.*      → 服务自身（server_info 等）
```

## 能力通道设计（按研究结论修正后的优先级）

1. **svc.\*（主力）**：`SCEModule.Editor.Current.Services.GetService(Type)` 取 DI 单例 → 反射调用。研究实证：FileSystem 等方法签名 >85% 是 string/bool/int/List\<string\>，天然 JSON 可调。高价值目标：FileSystem、EditorSettingsManager、SceneManager、PluginsManager。**服务级准入制（评审 R1）**：svc 目录**默认整体不开放**，annotations.json 按服务逐个准入后才进 search/invoke；未准入服务一律 `unsupported`。理由：研究只实证了参数侧 JSON 可表达，返回侧的引擎对象 getter 可能触 native 调用直接崩进程（不是托管异常，投影器的「跳过抛异常属性」防不住 native AV），必须逐服务人工扫描验证后再放行，不能默认全开靠黑名单堵。
2. **datacore.\*（手写封装，数编读写）**：走 `IDataCore`（AddMapScoped，地图加载后可用），手写 `datacore.list_entries` / `datacore.read(link)` / `datacore.write(link, path, value)` / `datacore.batch_write(changes, auto_commit)` 少数高层能力。不做 DataEditor nint 指针 API 的裸暴露。
3. **cpp.\*（次要）**：只收「静态方法 + 全基元/枚举参数 + 非 nint 返回」的条目（如 `cpp.DataEditor.IsMapLoaded`）。实例类（nativePtr_ 体系）不进目录——外部无法构造实例。
4. **cmd.\* / lua.\***：现有 Lua 桥，不变。
5. **sys.\***：server_info 等。

能力 ID 即原文（`cmd.调试/调试`、`svc.FileSystem.ScanDir`），走 invoke 的 JSON 字符串参数传递，不受 MCP tool name 字符集限制——中文/斜杠合法，客户端兼容风险低（tool name 只留 ~10 个固定英文词）。

## 固定元工具集（tools/list 全部内容，永不超过 10 个）

| 元工具 | 说明 |
| --- | --- |
| `search_capabilities` | 关键词搜索（id/描述/**别名**模糊匹配）。返回每条候选直接附**简化参数签名 + 一句话描述 + 风险级别**（compact schema），AI 可跳过 describe 直接 invoke |
| `describe_capability` | 完整定义：参数 JSON Schema、返回结构、风险级别、调用示例、前置条件（深查时用，非必经环节） |
| `invoke_capability` | 统一调用入口，按前缀路由执行器 |
| `list_namespaces` | 命名空间及各空间能力数，供逐层下钻 |
| `get_status` / `start_debug` / `stop_debug` / `restart_last_debug` | 高频调试操作保留直暴露（快捷路径） |
| `set_suppress` / `get_events` | 现有，保留 |

AI 交互链路设计（压低往返轮次）：

- **search 即得签名**：多数场景 search → invoke 两步完成，describe 仅疑难时深查。
- **invoke 参数错误自愈**：参数校验失败时，错误响应内**直接嵌入该能力的 schema**（相当于自动补发 describe），AI 下一轮即可自我修正，不需要显式再调 describe。**内嵌 schema 走 compact 形态**（评审 R5：与 search 输出同款的简化签名 + 必填/默认标注，非完整 JSON Schema 展开）——svc 方法含 List/嵌套对象时完整 schema 会膨胀成新的 token 噪音；完整 JSON Schema 仍由 describe 提供。
- **别名系统**：annotations.json 每条目支持 `aliases`（如 `["delete_file", "unlink"]`）与 `tags`（如 `["数编", "单位"]`），search 同时匹配 id/描述/别名/标签，大幅提升模糊搜索命中率。

0.4.x 的 `list_tool_categories` / `list_category_tools` / `cmd_uXXXX` slug 机制**直接废弃删除**（不做兼容）。

## 能力目录构建

- 新增生成工具（examples/ 同款定位）：反射扫描 sce.dll/scemodule.dll，产出骨架 catalog.json（id、参数签名含可选/默认值、返回类型、静态/实例、程序集来源）。svc 清单静态维护自两处 DI 注册表（sce.dll App.cs + scemodule Editor.xaml.cs）——IServiceProvider 无运行时枚举 API；工厂/扩展方法注册的盲区接受存在，靠运行期校验兜住（见下），不追求静态完备。
- **人工标注层 annotations.json**（仓库长期资产）：按 id 前缀补充中文描述、aliases/tags、风险级别、调用示例、黑名单。描述质量决定 AI 搜索命中率。
- catalog.json 编译期嵌入 dll，随补丁部署。
- **运行期惰性校验**：条目首次被 describe/invoke 时反射确认存在且签名匹配，不匹配返回「当前编辑器版本不可用」；catalog 头记录引擎版本并在 server_info 暴露，编辑器升级后重跑生成工具（并入 make_slots 同款「版本更新后重跑」约定）。
- **版本漂移主动通知（评审 R3）**：惰性校验发现不匹配、或启动时检测到 catalog 引擎版本 ≠ 当前编辑器版本时，置**持久 warning 状态**：推 `/events` 审计事件（`catalog_version_mismatch`），且 search 结果头部固定标注「目录版本漂移，部分能力可能不可用，请重跑生成工具」。避免「AI 搜到的能力一半不可用、无人知晓原因」的排查地狱。

## 执行器设计

### 共性约束

- **线程纪律**：引擎对象一律经 `BridgeWindow.DispatcherQueue.TryEnqueue` 调度，用 TaskCompletionSource 取回结果并设超时；禁止在执行路径上出现 `.Wait()`/`.Result`（防 UI 线程死锁）。
- **map-scoped 纪律**：svc/datacore 执行器复用现有 WaitForMapLoadedAsync 纪律，无图时对 map-scoped 能力直接返回「地图未打开」，绝不提前触碰 DI（MutiDebugWindow 崩溃前科）。

### 健壮参数绑定器（Binder，svc/cpp 共用）

- **重载消歧**：catalog id 无重载时保持 `svc.FileSystem.ScanDir`；有重载时生成显式后缀 `svc.FileSystem.ScanDir(string,bool)`。invoke 传入无后缀 id 且有多个重载时，按 JSON 参数的 key 集合/个数动态匹配最佳 MethodInfo；匹配歧义则返回全部候选签名让 AI 选择。
- **默认参数补齐**：漏传可选参数时自动填 `ParameterInfo.DefaultValue`，不允许直接 TargetParameterCountException 出局。
- **类型宽容**：枚举支持字符串名与数值双向解析；JSON number 到 int/long/float/double/decimal 做安全转换（溢出报错而非截断）；string ↔ 基元做合理互转。
- **Task 解包**：返回值为 `Task`/`Task<T>` 时自动 await（带超时）后再序列化结果。

### 返回值安全投影

- 基元/字符串/List 直接序列化。
- 复杂对象浅层投影：**最大深度 2**；跳过索引器、跳过求值抛异常的属性（getter 可能触 native/RPC 副作用）、跳过 Stream/IntPtr 等不可序列化类型；投影失败退 `ToString()`。

## datacore.* 封装细节

- **类型自动推导**：JSON → IDataType 递归映射表（bool→MakeBool、整数→MakeInt、小数→MakeDecimal、string→MakeString、array→MakeList、object→MakeProp、null→MakeNull）；path 支持字符串点路径与数组段。
- **批量原子写**：`datacore.batch_write({changes:[{link,path,value}...], auto_commit:true})`，全部 AddGameChange 后**只调一次 CommitChanges**——避免逐字段提交引发 20 次引擎同步/界面刷新。
- **单写约定**：`datacore.write` 默认 auto_commit=true（AI 友好，不遗漏落盘），可显式关闭配合批量。
- **commit 可撤销性前置实证（评审 R2，M3 开工第一步）**：CommitChanges 是真实落盘操作，必须先实证「commit 后能否经编辑器 Ctrl+Z / undo 栈撤销」。若**不可撤销**，则：单写默认改为 auto_commit=false（AI 必须显式提交，错误修改可重开地图丢弃），且 datacore 写类能力整体升级为 danger 级（需配置文件显式放行）。实证结论落盘到 mcp-capability-survey.md 后再定稿本节默认值。

## 安全分级与审计

| 级别 | 判定 | 策略 |
| --- | --- | --- |
| read | **仅**人工标注白名单或高置信纯查询（Is\*/Get\*/Query\*/Exists\* 且无副作用标注） | 默认开放 |
| write | **未知一律按 write**（不靠前缀猜 read——PopQueue/GetOrCreate 之类也会改状态） | 默认开放，describe 明示 |
| danger | Exit/Delete/SystemCommand/Publish/Upload… + 人工黑名单；**svc 未准入服务一律视同**（评审 R1）；datacore 写类视 R2 实证结论可能升级至此 | 默认拒绝，需在配置文件显式放行 |

- 放行清单放 `<引擎运行根>/logs/bgd_csharp/config.json` 同目录（与 mcp_port 配置同款机制）。
- **审计日志**：所有 write/danger 调用的「能力 id + 入参 + 耗时 + 结果/异常」异步写 `<引擎运行根>/logs/bgd_csharp/audit-YYYY-MM-DD.log`，便于误操作排查；危险拒绝同时推 `/events` 审计事件。

## 可读性改造（需求2）

1. JSON 序列化全局 `UnsafeRelaxedJsonEscaping`：中文不转义，所有出口统一走一个 helper。
2. 消灭 JSON-in-JSON：tools/call 的 content text 输出 pretty JSON；Lua 桥 ack 的 data 字符串在 C# 侧解析成对象后再并入响应，不透出原始转义串。
3. 能力 ID 即原文，无 slug；tool name 只剩固定英文词。
4. 错误结构化中文化：`{ok:false, error:{code, message, hint, schema?}}`，hint 给下一步建议；参数错误时 schema 字段内嵌完整能力定义（自愈反馈）。
5. search 结果一行一条摘要：`id — 中文描述 [risk]` + 简化签名。

## 协议端点

- `/mcp`：tools/list 固定集；tools/call 元工具分发。
- `/rpc`：search/describe/invoke/list_namespaces 注册为 rpc method（脚本直调）；旧 method 不保留（无用户，直接替换）。
- `/events`：不变；能力调用失败/危险拒绝推送审计事件。

## 开发约定（最后一公里固化，编码时直接照做）

1. **search 截断与打分**：`limit` 默认 5、上限 10；响应必带 `total_hits`（AI 据此自行收窄关键词）。打分链：精确 id 匹配 > aliases > tags > 中文描述模糊匹配，同分按 id 长度升序。
2. **batch_write 部分失败语义**：遇错即断。返回 `{ok:false, failed_index, error, applied_count, committed:false}` + hint「暂存未提交，重开地图即丢弃」。显式开关 `on_error: "abort"|"commit_partial"`（默认 abort）。数值类型模糊时 MakeInt 失败自动 fallback MakeDecimal 重试一次。
3. **UI 线程超时与模态卡死**：TaskCompletionSource 统一硬超时默认 5000ms，`invoke_capability` 允许 `timeout_ms` 按调用覆盖。超时除返回 TIMEOUT 外，日志标记「疑似模态阻塞」（防后续任务堆积雪崩），hint 建议结合弹窗抑制重试。
4. **错误 schema 固定契约**：参数校验失败（PARAM_INVALID）的 `error.schema` 一律为标准 JSON Schema 片段，但**保持 compact**：单层 properties、一行 description、不展开嵌套对象/$ref（嵌套类型以 `{"type":"object","description":"见 describe"}` 占位），控制自愈反馈体积（评审 R5）：

```json
{
  "ok": false,
  "error": {
    "code": "PARAM_INVALID",
    "message": "Missing required argument: path",
    "hint": "Provide 'path' as a valid directory string.",
    "schema": {
      "type": "object",
      "properties": {
        "path": { "type": "string", "description": "Absolute directory path" },
        "recursive": { "type": "boolean", "default": false }
      },
      "required": ["path"]
    }
  }
}
```

5. **反射异常解包**：`MethodInfo.Invoke` 抛出的业务异常必裹在 `TargetInvocationException` 里。执行器统一递归解包（`while (ex is TargetInvocationException) ex = ex.InnerException`），真实异常类型名填 `error.exception_type`、Message 填 `error.message`，绝不把反射壳透给 AI。
6. **序列化单例与投影深度分离**：全局统一 `JsonSerializerOptions` 单例只配两项——`Encoder = UnsafeRelaxedJsonEscaping`（消灭 `\uXXXX`）、`ReferenceHandler = IgnoreCycles`（防引擎对象循环引用崩溃）。**禁止**在全局单例上设 `MaxDepth = 2`——MaxDepth 读写双向生效，会把正常 MCP/rpc 请求体（嵌套 params）和错误自愈响应（4 层嵌套）全部炸掉；「最大深度 2」是返回值浅层投影器自己递归计数的实现细节，与全局序列化器无关。
7. **审计日志异步无锁**：audit 写入走 `Channel<AuditEntry>`（有界容量 1000 + `TryWrite` 丢弃），后台单线程消费写盘；审计丢了可补日志，绝不能文件句柄竞争反压阻塞 Gateway 主流程。

## 里程碑

| 里程碑 | 内容 | 验收 |
| --- | --- | --- |
| M1 序列化与可读性 | 统一 JSON 出口，消灭 Unicode 转义与双重转义 | curl 返回中文不转义、无双重转义 |
| M2 Gateway 骨架 + 元工具链路 | catalog 骨架（先只装 cmd.*/sys.* 现有能力）+ search/describe/invoke/list_namespaces 上线 + 执行器路由 + 删除 slug 机制 | 用现有 cmd.* 能力走通 search→invoke 端到端；tools/list 恒定 ≤10 个；旧 slug/category 工具不复存在 |
| M3 ServiceExecutor + 健壮 Binder | DI 服务反射、重载解析、类型宽容、Task 解包、UI 线程安全分发（含超时/死锁保护）+ 服务级准入机制 | invoke `svc.FileSystem.FileExists` 成功；可选参数漏传不炸；danger 被拒；**FileSystem 之外首个准入服务完成全方法面安全扫描**（隔离地图内逐个调用 read 级方法确认无崩溃，评审 R1） |

| M5 Catalog 工具链与标注层收敛 | 生成工具 + annotations（含 aliases/tags/服务准入）+ 自愈报错 + 版本漂移通知 | AI 客户端两步（search→invoke）完成一次 svc 调用；参数错一次后自愈成功；构造版本漂移场景能收到 /events 警告与 search 头部标注 |
| M6 实战验收与调优（评审 R4：量化口径） | AI 客户端接入真实复杂任务（如批量数编修改） | 长链路调用稳定；**tools/list 载荷 ≤ 4KB**（对比 0.4.x 全量 ~90 工具 schema 的实测字节数，降幅 ≥80%）；**典型任务（读数编→批量改 20 字段→启动调试）≤ 8 轮调用**（search 计 1 轮/次） |
| M7 | `run_lua` 兜底逃生舱（pcall 执行任意 Lua） | 默认 danger 关闭 |

先把 Gateway 骨架立起来、用已存在的 cmd.* 验证元工具链路，再往目录里灌 svc/datacore，每个里程碑都有可 curl 验证的真实产物。
